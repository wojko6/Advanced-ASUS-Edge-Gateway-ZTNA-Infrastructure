# Issue #84 — Edge Gateway WebUI Phase 2 validation

**Status:** PASS  
**Date:** 2026-09-29  
**Evidence class:** Live functional validation / sanitized  
**Reference platform:** ASUS TUF-AX5400 / Asuswrt-Merlin GNUton

## Purpose

Validate Phase 2 of the project-native ASUS Edge Gateway WebUI after extending
the Phase 1 read-only page with live Unbound runtime statistics.

The implementation remains read-only. It does not add Apply/Restart controls,
write DNS configuration, modify firewall policy, or replace the existing
project health check.

## Phase 2 implementation

Phase 2 adds a dedicated router-side status collector:

- `/jffs/addons/asus-edge/bin/webui-status`

The collector reads the active Unbound runtime through the existing Entware
binaries and `unbound-control`, then writes a sanitized JavaScript snapshot to:

- `/www/ext/asus-edge/status.js`

The ASUS WebUI page loads this snapshot and renders:

- Unbound version;
- runtime state;
- active listener and port;
- resolver uptime;
- query count;
- cache hits and misses;
- cache-hit ratio;
- SERVFAIL answers;
- DNSSEC secure and bogus counters;
- prefetch and serve-expired counters;
- average and median recursion time;
- snapshot generation time.

The snapshot is refreshed once per minute through Merlin `cru`.

## cru environment defect discovered during live validation

The first scheduled refresh exposed a platform-specific loader-environment
problem. The same collector that worked interactively produced an
`unknown/stopped/0` snapshot when executed by `cru`.

A controlled environment probe showed that Merlin `cru` supplied:

```text
LD_LIBRARY_PATH=/lib:/usr/lib:/lib/aarch64
```

Reproducing that exact environment manually caused the collector to generate
the same invalid zero/unknown snapshot.

Running the same collector with that inherited variable removed immediately
restored the expected Unbound values.

A separate test also showed that forcing
`LD_LIBRARY_PATH=/opt/lib:/opt/usr/lib` was not a valid workaround for this
collector path because it triggered a segmentation fault. That loader override
therefore remains limited to the already-validated boot-time Unbound recovery
path and is not reused by the WebUI collector.

## Fix

Commit `d86079d76429e86307148675b1185cda51d841de` changed the collector to:

- explicitly `unset LD_LIBRARY_PATH` before invoking the Entware Unbound
  tools;
- reject incomplete runtime snapshots while the Unbound process is still
  present;
- preserve the previous good `status.js` instead of replacing it with
  fabricated zero/unknown data after a transient collector failure.

The repository Validation suite completed successfully after the fix.

## Claim boundary

This evidence validates the Phase 2 read-only status and telemetry path only.

It does not validate future configuration write actions, Apply/Restart
workflows, generated Unbound configuration, cache mutation controls, firewall
editing, or other management functions proposed in issue #84.

SERVFAIL and DNSSEC-bogus values are diagnostic cumulative counters and may
overlap; the WebUI does not present them as independent outage counts.
End-to-end DNSSEC validation remains the responsibility of the project health
check.
