## Router disaster-recovery baseline — #100 / PR #101

After the post-firmware work closed, the session moved to disaster recovery
before starting additional router-side functionality.

### Read-only recovery inventory

A sanitized rebuild-manifest collector was added. It records reconstruction
metadata such as:

- model and firmware identifiers from an explicit allowlist;
- storage and swap topology;
- Entware package inventory;
- Tailscale package metadata plus live binary version/provenance;
- metadata and hashes for recovery-critical integration files;
- addon path inventory;
- Unbound and syslog-ng versions.

It deliberately excludes raw NVRAM output, Tailscale node state, authentication
material, configuration-file contents and private infrastructure identifiers.

The generated manifest was copied off-router, its SHA-256 manifest was verified,
and a manual sensitive-data review found only the collector's explanatory
exclusion text.

### Private NVRAM/settings export

A native ASUS/Merlin settings export was created and kept outside the public
repository.

The private artifact was:

- stored off-router;
- hashed locally;
- encrypted with symmetric GPG/AES-256;
- decrypted to a temporary file for verification;
- compared byte-for-byte with the original;
- confirmed with `DECRYPT_TEST_OK`.

No configuration-export bytes, credentials or private values were committed.

### Project backup and dry-run

A project-native backup was created on the reference router, copied to the
Fedora workstation together with its sidecar checksum, and verified off-router.

The exact copied archive then passed `restore.sh --dry-run`:

- every internal payload checksum passed;
- exact manifest coverage passed;
- the recovery payload was enumerated;
- no live router path was changed.

### Clean-room restore

The production restore implementation gained an explicit alternate-root mode
through `EDGE_RESTORE_ROOT`.

The exact off-router backup was restored into a disposable Fedora directory
instead of the live router. The test completed successfully, then a fresh source
extraction was compared with the restored target.

Observed results:

```text
CLEANROOM_JFFS_CONTENT_OK
CLEANROOM_OPT_CONTENT_OK
CLEANROOM_MODES_OK
```

This established byte-for-byte payload equality and regular-file permission-mode
preservation for the clean-room target.

### Unbound runtime ownership reconstruction

The reference router's manager-generated Unbound runtime directory requires the
documented ownership contract:

```text
uid=65534
gid=0
mode=0755
```

A temporary `/tmp` test on the router recreated this contract successfully and
returned:

```text
UNBOUND_RUNTIME_OWNERSHIP_RECONSTRUCTION_OK
```

The live Unbound runtime directory was not modified by this proof.

### Final post-mount restore safety correction

The final PR review caught an important recovery-boundary problem: an early
version of the backup stored `post-mount` under the normal live JFFS restore
tree.

That design was corrected before merge:

- new backups store the hook under
  `recovery-reference/jffs/scripts/post-mount`;
- the review copy is outside the automatically applied `jffs/` and `opt/`
  trees;
- `restore.sh` explicitly refuses to auto-apply
  `jffs/scripts/post-mount` from older backups.

The final restore implementation was tested against the older backup and
reported:

```text
Review-only: archived jffs/scripts/post-mount will not be applied automatically.
POST_MOUNT_NOT_AUTO_RESTORED_OK
```

This preserves the validated swap-order logic as recovery evidence without
silently overwriting a hook that AMTM may regenerate.

## Local HTTPS frontend for Grafana

The local Grafana operator path was then moved from a raw loopback URL to:

```text
https://grafana.home.arpa/
```

Caddy 2.11.4 was installed on Fedora and configured as a loopback-only reverse
proxy:

```text
127.0.0.1:443 Caddy -> 127.0.0.1:3000 Grafana
```

The Caddy configuration uses `tls internal`, binds explicitly to
`127.0.0.1`, and disables automatic HTTP redirects so no port-80 listener is
required. Grafana remains on its original loopback-only port and now advertises
the HTTPS root URL.

The packaged Caddy service could not install its internal root certificate
automatically because the `caddy` service account has no sudo privileges. The
public root CA was installed manually into Fedora's CA trust. The tested Brave
profile additionally required import into the user's NSS database.

Validation confirmed both listeners were loopback-only. The HTTPS request
returned HTTP/2 302 to Grafana's `/login` path through Caddy, and Brave then
loaded the local HTTPS URL without a certificate warning.

No Caddy private CA key is retained in the repository, and this change does not
expose Grafana to LAN, Tailscale or WAN.


## Grafana alerting baseline

Four provisioned alert rules were added to the external observability stack:

- SSH collector unavailable;
- router-reported WAN down;
- failed HTTPS/ICMP/router-DNS probe;
- stale router telemetry.

A controlled test stopped only the Fedora SSH collector. The collector and
telemetry rules moved through pending state and reached firing state, while the
independent blackbox Internet/DNS rule stayed healthy. Restarting the collector
returned all four rules to normal.

The test exposed a useful alert-dependency correction. The original WAN rule
treated missing collector data as a separate no-data state, even though a
collector outage does not prove a WAN outage. Its policy was changed to
`noDataState: OK`; missing telemetry remains covered by the collector and
freshness alerts.

Grafana was restarted after the change. Its health endpoint reported database
`ok` on version 13.2.2, and a journal query scoped after the new process start
found no matching error/failure entries.

## Centralized logging over Tailscale + mTLS

The previously documented syslog-ng design was promoted from configuration-only
status to live end-to-end validation.

The router was already running syslog-ng 4.10.2 with a TLS destination and
reliable disk-buffer. Fedora received syslog-ng 4.11.0 as the collector.

Before deployment, two router configuration directories that were mode 0777
were hardened to 0755; the TLS directory remained 0700 and the client private
key remained 0600.

The original router client certificate chained to an internal CA whose private
key was no longer available on the Fedora host or router. Rather than weaken
verification, a new dedicated logging CA was generated with an encrypted
private key kept off-router and outside the repository. New purpose-limited
certificates were issued:

- collector: `serverAuth`, Tailscale IP SAN;
- router: `clientAuth`, Tailscale IP SAN.

The Fedora collector was bound only to its Tailscale IPv4 address on TCP/6514.
The normal workstation firewalld zone no longer exposes TCP/6514. The
`tailscale0` zone uses default DROP with a single source-specific rich rule
allowing TCP/6514 from the router Tailscale /32.

mTLS was tested both negatively and positively. A connection without a client
certificate was rejected with `certificate required`; the issued router
certificate completed TLS 1.3 with verification OK.

The new router PKI was staged side-by-side, directly tested against the
collector, then referenced by a syntax-validated candidate configuration.
The active configuration remained unchanged until the final backed-up cutover.

A unique router test message was observed in both `/tmp/syslog.log` and the
Fedora date-partitioned collector file, proving the live path:

```text
Asuswrt -> router syslog-ng -> Tailscale -> mTLS -> Fedora syslog-ng -> file
```

A short collector-outage test then stopped Fedora syslog-ng, generated three
unique router messages, waited 15 seconds, restarted the collector and verified
all three messages arrived (`3/3`). This supports short-outage buffering/retry
but is not presented as proof of queue persistence through router reboot or
power loss.
