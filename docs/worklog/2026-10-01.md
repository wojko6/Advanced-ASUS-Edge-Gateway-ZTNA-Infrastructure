# Worklog — 2026-10-01

## RouterCloud versioned backups (#138)

Implemented and live-validated an independent versioned backup path for
Personal Cloud data.

Architecture:

~~~text
ASUS RouterCloud
    -> restricted read-only rsync pull
    -> Fedora staging mirror
    -> encrypted restic repository
    -> separate local NVMe
~~~

The backup SSH identity is restricted by a dedicated router-side forced-command
wrapper. It permits only the exact read-only rsync sender contract for the
RouterCloud path. Arbitrary shell access, wrong-path pulls and write attempts
were denied during acceptance testing.

The staging mirror uses `--delete` only on the Fedora receiver side so that
deleted RouterCloud objects are reflected in subsequent snapshots without
granting the backup identity delete capability on the router.

Version-recovery testing covered:

- restore of a file before overwrite;
- restore of the overwritten version;
- correct absence in the post-deletion snapshot;
- isolated full-directory restore;
- SHA256 verification of restored test data.

The encrypted restic repository uses an explicit retention policy:

~~~text
keep all within 48h
keep 14 daily
keep 8 weekly
keep 12 monthly
keep 3 yearly
~~~

`restic forget --prune` and a full `restic check --read-data` completed
successfully.

Backup automation runs through hardened user systemd units. The normal backup
runs every six hours and maintenance runs weekly. Persistence of the backup
mount, timers and a post-boot backup was validated after a real Fedora reboot.

## Backup observability

Only coarse operational status is exported to the local VictoriaMetrics
instance:

- last-run success;
- timestamp;
- duration;
- exit code.

No file names, RouterCloud contents, credentials or private keys are exported.

The `ASUS Edge Gateway — Engineering / CI` Grafana dashboard was extended with
`RouterCloud Backup` and `Backup Integrity` health signals. Both were
live-validated as `OK`.

During deployment, Grafana provisioning exposed a stale duplicate network
dashboard with the same UID and title as the active dashboard. The duplicate
was moved outside the watched provisioning directory with rollback retained.
Provisioning then accepted the updated Engineering / CI dashboard and all nine
Infrastructure Health signals rendered successfully.

Repository artifacts for #138 include the validated router-side read-only
wrapper, Fedora backup/maintenance/metrics scripts, systemd units, environment
example, Grafana changes and the restore/runbook documentation.

## Syslog-ng local-archive resilience (#156)

A separate reliability incident was reproduced in the router logging path.
`syslog-ng` itself remained alive and retained the current
`/tmp/syslog.log` inode, while its source file descriptor stopped at byte
65536 even though the Asuswrt source file continued growing beyond 243 KiB.
Fresh `logger` probes were visible in the source file but did not reach the
router-local syslog-ng archive.

Root-cause analysis identified hard `flags(flow-control)` on the shared
local-plus-remote fan-out path. This coupled local archival progress to
backpressure from the remote Fedora collector.

The remediation removed hard flow control from the combined fan-out while
preserving the remote destination's reliable disk buffer and mTLS transport.
This keeps the router-local archive available when the remote collector is
temporarily unavailable.

Live fault-injection validation covered:

- normal-path marker delivery to the Asuswrt source, local archive and Fedora;
- intentional collector outage on TCP/6514;
- successful local archival of a new marker during the remote outage;
- exact catch-up of the syslog-ng source FD to the source-file size;
- collector restoration and TLS reconnection;
- delayed delivery of the outage marker to Fedora after recovery.

The exact queue occupancy at the original stall was not measured, so no
specific queue-full threshold is claimed.

A static regression guard was added to `tests/test-static.sh`. It rejects a
reintroduction of hard `flags(flow-control)` on the public router example and
also verifies that both local and remote destinations remain present.

The fix, evidence, case study and regression coverage were merged in PR #156
(`fix(logging): keep local archive available during collector outages`).
