Build performed on a separate Fedora 45 workstation; router deployment and smoke tests were operator-executed. ## Controlled ARMv7 update: Tailscale 1.104.4 → 1.104.7

- **Provenance:** upstream tag `v1.104.7`, source commit `cbc74fe48ef1b1649f69a4d9a602319427e25102`. Fedora 45 local Go `1.27.4-X:nodwarf5`, cross-compile `GOOS=linux GOARCH=arm GOARM=7 CGO_ENABLED=0`. Initial `go mod download` failed with an HTTP/2 INTERNAL_ERROR; a retry using `GODEBUG=http2client=0` succeeded. `go mod verify` reported all modules verified.
- **Artifacts:** statically linked ELF32/ARM EABI5 CLI and daemon. SHA-256: CLI `3f2e55fb64001e7a5470e0b253081a69886a7fb5688b3c56dea63a36e6669ff2`; daemon `b1978882a914c27ae67ba147a1dce2d899f96bb659f529821b66f594597b559b`. Hashes were rechecked after LAN-only transfer to an isolated staging directory. Staged CLI executed on the ARMv7 router and reported `1.104.7`.
- **Observed pre-update state:** active CLI/daemon `1.104.4`, while Entware package metadata remained `1.96.1-1`; this is **package/live binary drift**, not an Entware-managed upgrade. Two daemon-path spellings resolved to the same device and inode. The live process used the active state file selected by the Entware service. A second, distinct state file existed; the ASUS Edge startup script sources its external configuration, which overrides the script's fallback and agrees with the live state path. No state consolidation or script edit was necessary.
- **Recovery evidence:** protected on-device backup of the previous CLI, daemon, both state files, the full daemon-state directory and service/hook scripts; operator-reported `BACKUP_VERIFICATION=PASS`, approximately 66.6 MB. This backup resides on the same attached Entware volume and is **not an independent off-device disaster-recovery copy**. Restore and failover were not exercised.
- **Maintenance action:** an explicitly launched detached local runner stopped the existing Entware daemon, snapshotted its active state, promoted the two checked ARMv7 binaries, restarted the managed service and ran a bounded Local API/IPv4 continuity check. Runner log reported `TAILSCALE_G9H_SWITCH=PASS`, `DAEMON_HEALTH=PASS` and `TAILSCALE_IP_PRESERVED=PASS`; rollback was available as a best-effort error path but **was not triggered or tested**.
- **Post-update read-only verification:** both live hashes matched the staged files; `tailscale version` and the actual executable via `/proc/<pid>/exe --version` reported `1.104.7`, commit above and Go 1.27.4. Single live daemon, Local API `BackendState=Running`, original Tailscale IPv4 preserved, connected Fedora peer reported as direct, and `tailscale status` continued to advertise exit-node capability.
- **Client exit-node IPv4 smoke:** mobile-data public IPv4 changed from a cellular-provider egress address to the same public IPv4 observed over the home Wi-Fi after selecting the ASUS exit node. This supports a working IPv4 exit path. Equal public IPv4 on home Wi-Fi with/without Tailscale is expected but is **not independent proof of tunnel traversal**.
- **IPv6 configuration observation:** router `nvram get ipv6_service` returned `disabled`; `ip -6 route show default` was empty. This confirms the router WAN IPv6 setting/default-route state at test time, **not** a complete IPv6 leak assessment for every client.
- **Out-of-scope:** no DNS leak test, Pi-hole/Unbound/DNS Guard packet-path correlation, firewall policy change, full router healthcheck, clean-boot persistence test, off-device restore or long-duration stability test during this session. Do not mark them PASS from this result.
