## RouterCloud / Dufs issue #235 — isolated HTTP origin hardening

- Lab work reproduced an **expected-red custom HTTP 404** case: a user-controlled HTML page could be sent inline as a custom error response without a restrictive CSP. A regression was added; a candidate change restricted trusted custom error assets.
- Further isolated red tests showed trusted login/versioned asset routes traversing symbolic links into user data. Source hardening addressed path-component and symlink trust checks; tests covered asset routes, authenticated UI and the startup index.
- Active user-file content handling was constrained through attachment disposition, sandbox CSP and `nosniff`, with regression consideration for WebDAV, standard downloads, Range/multipart and legitimate static UI assets. Browser-inline optional render-index/render-spa compatibility requires a separate explicit decision.
- The V2 lab checkpoint consolidated repeated user-file content/metadata/MIME path opens around a single file descriptor; the operator reported `ISSUE235_SINGLE_FD_V2=PASS` after Rust tests. **A remaining trusted-assets validation-to-open race was not resolved at this date's final checkpoint**; true directory-FD-relative trusted opening was the next task.
- The working Dufs tree remained local/unmerged/unreleased at the end of this date; no ASUS service restart, binary deployment, permission migration or verified remote exploit. See [issue #235](https://github.com/wojko6/Advanced-ASUS-Edge-Gateway-ZTNA-Infrastructure/issues/235) and separate documentation [PR #238](https://github.com/wojko6/Advanced-ASUS-Edge-Gateway-ZTNA-Infrastructure/pull/238) (open, not merged at subsequent review).
