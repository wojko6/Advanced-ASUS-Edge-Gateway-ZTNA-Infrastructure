- An initial check found no system `ollama` command or listener. The operator launched an existing portable Ollama runtime, confirmed API version **0.40.11** and listed local **Qwen3.5 4B** GGUF (Q4_K_M). A local model check reported `PASS_MODEL_LISTED_LOCAL_ONLY`.
- KDE desktop launcher and browser chat operated on the user's workstation. The supervised GUI evolved from **v0.1 to v0.10.1** during this session.
- **v0.3–v0.4:** one Send button, explicit approval for a bounded DNS-read operation and result interpretation.
- **v0.5–v0.7:** selected service/log checks, application launches, bounded file copying and counted log samples.
- **v0.8/v0.8.1:** allowlisted read-only diagnostics and launch of specific trusted apps no longer require an extra confirmation; state changes still do.
- **v0.9–v0.9.2:** fixed five-step monitoring workflow, a separate health assessment (`OK/WARNING/ERROR/UNKNOWN`) from execution completion, and fixed-endpoint Grafana manifest-metrics inspection.
- **v0.10/v0.10.1:** bounded UTF-8 workspace text preview without approval; file rename with single-use approval and no overwrite; task-specific concise file feedback instead of unrelated infrastructure analysis.
- Operator screenshots confirmed both a permitted file read and an approved rename, followed by the concise v0.10.1 file response. The last creator-reported suite was **134/134 offline PASS**, **not** a GitHub CI result.

## Monitoring and Grafana observations

- One `systemctl is-active` read reported `active` for Grafana, Loki and VictoriaMetrics, which is not full service-health proof.
- An earlier UI HTTP sample returned **503 for Loki**. A **separate later direct check** returned `/ready` **HTTP 200** with `ready`, and `/services` **HTTP 200** with 16 components `Running`. The cause of the earlier 503 was not established; no sustained outage is claimed.
- An updated five-step report completed 5/5 reads and assigned overall `WARNING` because of Grafana warnings, not a Loki outage.
- Repeated `search-manifest-watcher` messages reported empty discovery results. Metrics showed **0 loaded manifests**, **0 reloads**, and an increasing *cumulative* `empty` poll count (**304**, later **315**). A successful HTTP metrics read or `last_success` marker is not proof of loaded manifests.
- Ordinary Grafana UI dashboard search returned existing ASUS dashboards for the operator's query. It does not certify the separate manifest search subsystem. Treat as a **component-scoped WARNING**, not established router DNS/Unbound failure. No Grafana configuration changes or log suppression occurred.

## Privilege and deployment boundaries

The desktop UI can execute **limited, allowlisted user-session actions**, with extra consent for approved mutations. **Do not conflate this with the separate C.63 Local AI Agent** whose published laboratory gate remains `MODEL_ACTION_AUTHORITY=NONE`. The GUI has not been independently security-audited, and its tool/approval code is absent from this repository. Reading files may expose contents to the local model; GUI app launches have indirect side effects. Arbitrary shell/`sudo`, autonomous router action, arbitrary file edits/deletes, and Wayland input control are not authorized.

No ASUS production update, HCC permanent deployment or autonomous-agent rollout was performed as part of this UI work. **`DEPLOYMENT_GATE=HOLD`** for the agent/HCC tracks.
