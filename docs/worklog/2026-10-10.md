## Client DNS failover: off-router experiments (#212)

1. **RC1–RC12:** Fedora isolated source-copy and private-network-namespace tests explored selected-source LAN/Tailnet DNS fallback, UDP/TCP DNS, NAT/filter INPUT/FORWARD paths, generational selectors, synthetic Pi-hole failures, rollback and conntrack pinning. RC11b actual isolated routed FORWARD and RC12 router-local INPUT/conntrack gates returned PASS within their lab scopes; existing UDP mappings remain pinned, and real ASUS behavior is not proven.
2. **RC13 router read-only inventory:** TUF-AX5400, GNUton 388.11, Linux 4.1.52 ARMv7, iptables 1.4.15 and firmware dnsmasq 2.91. The deployed `/jffs/scripts/firewall-start` is a 339-byte managed wrapper; its `/jffs/addons/asus-edge/bin/firewall-start` target is 19,022 bytes and has SHA-256 `5bca3badd1b083e8e886d0fc3b550a467b6cdd407e4c03b530668041e43c39c8`, matching the pinned **original** source used in labs. The legacy-hook flag was off. This does **not** mean experimental #212 changes were installed.
3. **Boot and lifecycle review:** the Entware service scripts S61unbound, S64pihole-ip and S65pihole-FTL were inventoried; Unbound listens on the configured loopback port 53535. DNS Guard uses a one-minute cron watchdog. The two observed firmware dnsmasq processes were a parent/child pair, **not** redundant resolvers. Review of the tagged GNUton `stop_dnsmasq()` / `killall_tk()` logic revealed process-name termination risk for a same-name standby.
4. **RC13 private process test:** in disposable Fedora PID/network namespaces, a name-scoped stop terminated ordinary-named dnsmasq processes while a temporarily renamed standalone resolver remained available over UDP/TCP. **RC13_PRIVATE_PROCESS_LIFECYCLE_LAB=PASS**; the ARMv7 binary, native ASUS restart and privilege boundary remain untested.
5. **RC13b SmartDNS comparison:** a portable, SHA-verified **x86_64** SmartDNS 48.4 archive was tested against renamed Fedora dnsmasq with synthetic UDP/TCP upstream, private A/PTR records, unknown private-name non-leak and bounded stop. **RC13B_PRIVATE_DNS_PARITY_GATE=PASS.** One Fedora snapshot showed RSS 5,820 KiB for SmartDNS and 6,248 KiB for renamed dnsmasq; this is **not** a router benchmark or an ARMv7 compatibility finding.
6. **RC13c cryptographic preflight:** dnspython 2.8.0 plus cryptography accepted a correctly signed synthetic Ed25519 RRset and rejected a forged A with unchanged signature. **RC13C_CRYPTOGRAPHIC_FIXTURE_GATE=PASS.** A separate isolated dnsmasq/SmartDNS full DNSSEC resolver test archive was **prepared but not operator-executed**. **RC13C_FULL_RESOLVER_GATE=PENDING**, not PASS. In particular, no self-validation-versus-passthrough conclusion has been made for SmartDNS.

One accidental download-only attempt for the x86_64 SmartDNS archive on ASUS returned curl error 23 (destination directory absent). A read-only follow-up found no archive and no SmartDNS process. No new listener, firewall/NAT/DHCP/conntrack mutation, DNS service restart or client failover was performed as part of #212; **ASUS_MODIFIED=NO** for the documented tests. Laboratory code was not committed/pushed/merged. Preserve the current production Pi-hole/Unbound path and independent **router-system DNS Guard v3.2** baseline; it must not be confused with proposed **client** failover.

**Next engineering gate:** run RC13c within the private rootless Fedora namespaces; evaluate bogus/valid DNSSEC resolver behavior, actual ARMv7 and GNUton lifecycle compatibility, supervision/privilege boundaries and failback. A later explicitly authorized single-client router pilot requires its own staged firmware checks and rollback. Issue #212 stays **OPEN / NOT DEPLOYED**.

## Custom BusyBox: latest-reboot persistence (#129)

The 2026-10-09 worklog correctly described an earlier checkpoint before this proof and is retained as history.
