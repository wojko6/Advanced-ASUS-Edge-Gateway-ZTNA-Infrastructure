### 2. Source/installation ownership hypothesis

The repository's [`router/scripts/services-start`](../../router/scripts/services-start) registers both named Cron jobs. [`scripts/install.sh`](../../scripts/install.sh) requires root, but its `install_file` implementation writes an existing destination with `cp "$src" "$dst"` and `chmod "$mode" "$dst"`; it does **not** explicitly normalize the resulting owner/group with `chown`. Independent isolated GNU/BusyBox copy tests demonstrated that a pre-existing foreign-owned destination can preserve UID/GID across overwrite. This is a **plausible cause** of persistent ownership drift, not evidence that this particular live installation followed that history.

Do **not** use the generic installer as a quick repair; it can also replace customized JFFS hooks and interfere with the independent SSD/RouterCloud work.
