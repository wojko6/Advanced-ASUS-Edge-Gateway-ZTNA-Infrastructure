## Later November 4 checkpoints — USB trial, ACPI/TSC and Fedora 45 (operator-reported)

> **Chronology and scope:** the preceding `ocvalidate` section describes an earlier **read-only** check. The following independent checkpoints happened *later* that day, including **one separately approved write to the external test USB**. Their results do not revise the earlier read-only observation. The source for these statements is the operator's separate laboratory output; they are not independent GitHub CI or production acceptance.

### Sonoma recovery provenance and controlled test-USB change

- Compared the three OpenCore boot/runtime binaries to the **1.0.8 RELEASE** distribution; the operator reported **3/3 matching**. This supports file provenance in the checked subset but not runtime boot success.
- The external test USB's EFI tree was backed up and hash-checked (**67 files**), and the Recovery chunklist check passed **76/76** fragments. Internal `SystemVersion.plist` identified **macOS Sonoma 14.6.1**. The chunklist check did not separately validate an Apple code signature; a USB volume label suggesting Tahoe is not a macOS version identifier.
- After backup and a bounded comparison, the operator explicitly approved **B226**, which changed **only** the test USB's OpenCore `NVMeFix.kext` enable flag from on to off. `ocvalidate` and comparison checks passed; no internal Fedora EFI, other NVMe, or BIOS write was reported. Thus the original `USB_WRITES=NO` refers to the earlier single static-check operation, **not to all work on November 4**.
- The two subsequent **B227 external USB boot attempts** did **not reach Recovery**. The first ended in an operator-confirmed autonomous restart after the boot path advanced; the second showed further kernel/ACPI output but its ultimate restart/freeze outcome was not unambiguously confirmed. Earlier output with NVMeFix on included AppleNVMe messages. This **does not** establish NVMeFix as the root cause.

### ACPI and TSC findings (read-only Fedora diagnosis)

- A firmware ACPI namespace error involving `PB2 / AE_NOT_FOUND` was also observed in a functioning Fedora boot and, in the operator's historical log comparison, in **4/4** inspected boots. This alone does not prove that ACPI is blocking Sonoma.
- On the running Fedora host, Linux reported **TSC synchronization failure** and selected **HPET** as the clock source. Similar warnings appeared in macOS verbose output, making TSC a specific **investigation hypothesis**, not a proven macOS boot failure mechanism.
- No firmware/NVRAM fix, bootloader replacement or follow-on installer attempt was authorized. No new successful recovery or graphics/runtime acceptance is claimed.

### Separate Fedora 45 / NVIDIA preflight

- In a distinct **no-RPM-change** investigation, the operator compared Fedora 44→45 packages: `scrcpy 5.0.1` for FC45 requires FFmpeg 9 ABI and providers were found; the Fedora 45 `tgerov/vpcs` COPR endpoint returned a 404. Retaining the FC44 VPCS package was not runtime-tested.

A separate targeted solver demonstrated a consistent NVIDIA **615.78.08** candidate, **not** an installation.

DNF5 could query the repository and three chosen RPMs passed checksum checks. This does **not** certify signatures, package provenance or working graphics/akmods. **B9 (full Fedora 45 + NVIDIA 620 transaction) was proposed but NOT RUN.**

A later Secure Boot read differed from prior checkpoints; the cause was not established. `INSTALLATION_GATE=HOLD`.
