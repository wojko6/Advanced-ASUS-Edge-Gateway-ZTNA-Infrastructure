## RouterCloud Grafana alerting — PR #190

The Grafana baseline was extended from five to nine rules. Four new rules cover
RouterCloud backup/maintenance failure and staleness:

- `routercloud_backup_bad`;
- `routercloud_backup_stale`;
- `routercloud_maintenance_bad`;
- `routercloud_maintenance_stale`.

All nine current rules route to the existing `ASUS Edge Gateway Email`
contact point. Resolved notifications remain enabled.

A new operator-run live test,
`tests/test-grafana-routercloud-alerting-live.sh`, performs a controlled
synthetic failure against the local VictoriaMetrics success metric, waits for
Grafana `Alerting/Firing`, restores the real healthy metric from RouterCloud
backup state, and requires recovery to `Normal` or no active alert instance.
The script is intentionally excluded from normal CI because it mutates live
local metrics and may generate real notifications.

The controlled test passed. Final state:

- healthy RouterCloud backup metric restored;
- no active `routercloud_backup_bad` alert instance;
- repository/live alert provisioning equal;
- repository/live e-mail contact provisioning equal;
- nine rules present and routed to the e-mail receiver;
- static regression suite passed.

The live evidence is published as
[Grafana RouterCloud alerting — live validation](../../evidence/2026-10-07/grafana-routercloud-alerting-live-validation.md).
