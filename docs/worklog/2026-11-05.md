# 2026-11-05 — Fedora supervised Qwen GUI, bounded health checks, and Loki readiness investigation

> **Sanitized public engineering chronology; operator-reported workstation evidence.** The Python GUI prototype, full logs, screenshots, local paths, KWin identifiers, and any user-session artifacts are **not published in this repository**. The offline test counts below are creator-reported, not independent GitHub CI or security certifications. This is **not** an ASUS production deployment. The separate C.63/C.64 laboratory agent and supervised desktop GUI retain distinct authority boundaries.

## Supervised GUI progress

- **KWin/WindowsRunner:** bounded read-only D-Bus `Match` aggregates were added with sanitized icon-family and opaque search-match group counts. Search matches and repeated opaque IDs are **not** verified window counts, application/process identities, or the active window. A comparison of 378 public `.desktop` entries supplied only heuristic category hints. No KWin `Run`, scripting, window control, or private title disclosure was part of these checks.
- **v0.12.13–v0.12.21:** query-parameter-safe GET routes, stale-response isolation after “New conversation”, fixed three-step resource overview (`uptime`, `free`, `df`), deterministic resource summaries, cards for resources/network/monitoring, sample timestamps, and bounded technical-report expansion. After the operator observed nested scrollbars, **v0.12.21** was changed to a single scrollable diagnostics panel; the operator confirmed the scroll behavior on Fedora.
- **v0.12.23–v0.12.25:** five quick-task choices (inserting but not automatically submitting questions), bounded natural-language variants, clarifications for ambiguous memory questions, and reviewed multi-turn follow-ups about disk space, Grafana manifest metrics, and network configuration limits. The operator confirmed these scenarios in the GUI. These are explicit mappings, **not unrestricted natural-language tool planning**.
- **v0.12.26:** a specific Internet-connectivity question triggered a fixed two-endpoint HTTPS check rather than treating `ip route` as proof of Internet access. The operator reported **2/2 successful Google/Cloudflare HTTPS checks** at the time tested. This does not establish universal Internet availability; the fixed external requests expose normal network metadata to their respective providers, not chat content.
- **v0.12.27–v0.12.29:** predetermined DNS resolution (`example.org`), local service-active/readiness comparisons, bounded RAM/disk capacity heuristics, and consistent sample-status labels. In **v0.12.29**, successful `uptime`/`free`/`df` executions with an ungraded health state are labelled **“read completed — without full health assessment”** rather than “failed to assess”. Operator screenshots confirmed that behavior. Latest creator-reported offline suite: **338/338 PASS**, plus **4/4 simulated local HTTP cases**; no independent host-wide security audit.

## Loki readiness — an intermittent, component-scoped observation

- The supervised GUI intermittently observed `/ready` HTTP **503** while the systemd unit remained `active`. A direct bounded `/ready` and `/services` probe returned **8/8 HTTP 200** and **16/16 services `Running`** on one occasion.
- A later **event-triggered, foreground, read-only** probe captured an initial 503 and two more 503 follow-ups on **2026-11-05 at 18:11:34–18:11:36 CET**, categorized as **`INGESTER_NOT_READY`**. At the trigger, `/services` reported all 16 components `Running`; systemd was active, with no restart observed. This identifies the readiness check affected, **not** the underlying root cause.
- A subsequent bounded probe observed **45/45 HTTP 200** without a 503 trigger; this does **not** demonstrate that the intermittent issue was fixed. No production Loki restart, configuration change, or background watcher was installed.

## Grafana manifest watcher vs. tested dashboard functionality

- Bounded `journalctl` samples contained `search-manifest-watcher` warnings about empty discovery/keeping the previous set. One operator-reported metric sample showed **0 loaded manifests**, **196 cumulative empty polls**, **196 cumulative empty discoveries**, and **0 reloads**. These counters are not the number of dashboard failures.
- The operator separately opened an existing ASUS monitoring dashboard, observed populated telemetry charts, and successfully searched for that dashboard through Grafana's visible search control. This **confirms the tested UI paths**, but does not certify the special manifest-discovery subsystem. No Grafana settings, dashboard definitions, or logging configuration were modified.

## Safety, evidence, and release boundary

The GUI is a local, supervised allowlist executor for selected reads/launches, with approval for bounded state changes. It is not the distinct C.63/C.64 research agent with `MODEL_ACTION_AUTHORITY=NONE`. Neither track authorizes arbitrary shell commands, `sudo`, autonomous router operations, open-ended filesystem writes, or Wayland input control. Local source and raw workstation evidence remain outside this public worklog.

**Closing point:** operator-validated GUI presentation for **v0.12.29**, with **`DEPLOYMENT_GATE=HOLD`**. Unresolved: intermittent Loki ingester readiness and manifest-watcher warnings without demonstrated failure of ordinary dashboard search. No production change or broader deployment acceptance is claimed.
