# Engineering worklog — 2026-10-08

This entry records the DNS Guard break-glass recovery hardening performed on
2026-10-08. The published checkpoint is PR #197; the later hardening increment

## DNS Guard recovery failure analysis

An earlier router-side break-glass rehearsal did not pass the complete on/off
recovery path. The live router was returned to its healthy DNS state before
further development. The subsequent supervisor, installer and regression work
was performed off-router; no production deployment of the new ARMv7 supervisor
is claimed.

The break-glass helper was hardened to preserve WAN DNS NVRAM state before
arming sticky break-glass, reject invalid snapshots, restore partially changed
NVRAM values, retry transient bootstrap/IP/DNS failures and enforce a
monotonic total bootstrap budget. Failure paths retain recovery evidence and
return nonzero rather than claiming DNS recovery.

## Process supervision and verified ARMv7 artifact

A native Linux supervisor was added as
`router/src/edge-dns-supervisor.c` and packaged at
`router/bin/edge-dns-supervisor`. It uses a monotonic timeout, process
group cleanup and Linux child-subreaper handling, including orphaned
descendants that escape the original process group. Native regressions cover
exit status, bounded timeout, descendant reaping and `flock` release.

The binary was cross-compiled as a static ARMv7 EABI5 soft-float ELF using
the Debian Bookworm armel cross toolchain. A QEMU 7.2 user-mode limitation
initially prevented `PR_SET_CHILD_SUBREAPER`; QEMU 10.0.13 successfully
executed the ARM binary. Emulated regressions passed for normal/failure exit,
timeout, ordinary children, escaped-session descendants and released locks.
These are emulation results, **not a live firmware runtime acceptance**.

`scripts/install.sh` now verifies the packaged artifact SHA-256 before
changing installation state and installs it under the managed `bin`
directory. The existing directory snapshot/restore mechanism covers the
binary. Isolated installer regressions passed for a valid install, corrupt
artifact rejection before mutation, and rollback to the previous binary.
`scripts/build-dns-supervisor-armv7.sh`, documentation and CI checks provide
source-to-binary byte parity verification.

## Additional local hardening after the green CI run

Two local files were edited after `a973a33`:
`router/scripts/edge-dns-breakglass.sh` and
`tests/test-dns-breakglass.sh`.

The helper's final `nslookup` check was moved from a direct-child watchdog
to the supervisor. A new regression verified that an escaped DNS lookup child
is reaped and its `flock` is released.

Read-only inspection of the reference firmware confirmed that
`/sbin/service` links to `rc`. Corresponding firmware source inspection
showed that `service restart_wan` dispatches an `rc` notification; a
successful exit acknowledges submission, **not completed WAN recovery**.
The helper's WAN dispatch was therefore supervised, while WAN/IP/DNS readiness
remains checked independently. The previous direct-child watchdog was
removed.

A per-invocation single-dispatch guard prevents the same helper invocation
from submitting a second ambiguous WAN restart request during recovery/rearm.
Local regressions passed for a hung dispatch and a failed WAN-IP check:
`WAN_TIMEOUT_SINGLE_DISPATCH=PASS` and
`WAN_IP_FAILURE_SINGLE_DISPATCH=PASS`.
The updated break-glass regression, static suite, ShellCheck and diff check
also passed. **These later changes have not yet been committed, pushed or run
in GitHub Actions.**
