## Issue #84 — Edge Gateway WebUI Phase 2

Phase 2 of the project-native ASUSWRT WebUI was deployed and live-validated.

The existing read-only page now exposes Unbound runtime telemetry through a
dedicated `webui-status` collector and a one-minute Merlin `cru` refresh.
Displayed values include the Unbound version/listener, resolver uptime,
query/cache counters, cache-hit ratio, SERVFAIL and DNSSEC diagnostic counters,
prefetch/serve-expired values, recursion timing and snapshot age.

Live testing uncovered a firmware cron-environment defect: `cru` inherited
`LD_LIBRARY_PATH=/lib:/usr/lib:/lib/aarch64`, causing the Entware Unbound tools
to fail and the first scheduled collector version to overwrite the page with
zero/unknown values. The failure was reproduced under the exact cron
environment. Removing that inherited variable restored correct reads; forcing
`/opt/lib:/opt/usr/lib` was explicitly rejected after it caused a segmentation
fault in this collector path.

Commit `d86079d76429e86307148675b1185cda51d841de` now unsets the inherited
loader variable in the collector and preserves the previous good snapshot when
a runtime collection is incomplete.

Post-fix validation confirmed that the actual scheduled job generated fresh,
non-zero Unbound data at the next minute boundary while the resolver retained
the same PID. The live ASUS page rendered the Phase 2 metrics correctly.

The final full project health check completed with:

```text

```

Sanitized evidence is recorded in
`evidence/2026-09-29/issue-84-edge-gateway-webui-phase2-validation.md`.

## Issue #133 — persistent Polish ASUS WebUI overlay

The Polish ASUS/GNUton WebUI localization moved from a manually staged
candidate to a reproducible project-owned deployment path.

Four reviewed firmware-resource deltas are now represented as unified patch
files for `PL.dict`, `help.js`, `Tools_Sysinfo.asp` and
`Tools_OtherSettings.asp`. Complete ASUS firmware resources are not added to
source control.

Entware GNU patch 2.8 was installed and tested on the reference TUF-AX5400.
Applying the repository deltas to clean firmware resources reproduced all four
previously accepted Polish artifacts byte-for-byte, including their expected
SHA-256 hashes.

A fail-closed `webui-pl-build` helper was added. It accepts only the pinned
stock firmware hashes or the already validated Polish hashes, builds the
resources during install/update, and rejects unknown baselines. GNU `patch` is
therefore an installation-time dependency only; the early-boot path remains
independent of `/opt`.

Runtime persistence is handled by `webui-pl-mount` and integrated with the
existing `webui-mount` lifecycle. Early boot uses the firmware OpenSSL binary
for SHA-256 validation, then bind-mounts the prepared JFFS resources and
localizes the generated menu tree.

Validation completed successfully for both build paths:

- active-overlay reinstall/update -> `WEBUI_PL_BUILD=PASS`;
- stock-firmware fresh build -> `WEBUI_PL_BUILD=PASS`;
- mount/unmount/remount lifecycle -> PASS;
- reboot persistence -> PASS;
- final live hashes matched all four accepted artifacts;
- project health check -> `0 failure(s), 0 warning(s)`;
- repository static suite -> `TEST_RC=0`.

This leaves the localization implementation reproducible without committing
complete vendor WebUI files to the repository.
