## V0.14.5D — synthetic record identity and consistency (Work only)

Continued under the standing authorization for autonomous safe test development.
The existing four-field sanitizer output omits source-record identity and
millisecond truncation can merge distinct-looking records. Implemented a
[separate synthetic envelope/identity model](../../experiments/fedora/homelab-control-center-v0.1/V0.14.5D-SYNTHETIC-EVENT-IDENTITY-LAB.md),
without modifying the existing sanitizer or A–C modules.

Input permits only boot/cursor/time_us/fixed unit/fixed class, 128 rows / 64 KiB.
Integer microsecond conversion preserves distinct times. Domain-separated
HMAC fixture IDs bind boot/cursor/unit; a separate key-scope tag prevents silent
scope changes within one ledger. Only canonical sanitized output is retained.
Same identity with changed time/kind causes HOLD; exact envelope replays are
recognized across overlapping batches. The bounded 1,024-entry ledger validates
the entire batch before commit; conflict/capacity/schema errors do not partially
update it. Scope remains unbound after a rejected initial batch.

This is **synthetic declared-source metadata**, not a trusted journal reader or
authentication. The deterministic key is public and has no production lifecycle.
No source fields are read from the host, and the CLI has no stdin/path/key/URL
input. Ledger state is memory-only; a fresh ledger reaccepts old IDs. IDs are
record identifiers, not collector-run IDs or incident counts. The seven-field
microsecond schema deliberately fails the old A–C validator; no downgrade or
spool integration was added.
