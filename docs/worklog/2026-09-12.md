# Engineering worklog — 2026-09-12

## Summary

This session focused on repository-side hardening while the reference router remained inside the unchanged-state Stability Gate. The work expanded configuration validation, failure propagation, recovery checks, evidence boundaries, endpoint-filtering methodology, and CI coverage without changing the validated router configuration.

## Runtime and configuration hardening

Repository scripts received a broad fail-fast validation pass. Firewall booleans, ports, interfaces, IPv4 addresses/CIDRs, WAN recovery timing, services-start timing, health-check inputs, and the optional syslog health target were validated before mutable runtime actions. Dynamic WAN detection was also moved behind a prevalidation boundary so an invalid WAN state could not partially rebuild the firewall.

Tailscale startup policy application and the required managed firewall hook were changed so failures propagate as real startup failures rather than warning-only success.

## Recovery and maintenance safety

Restore archive validation, Tailscale update recovery guards, uninstall failure reporting, and temporary firewall guard cleanup were strengthened. The update path now distinguishes a failed package query from a genuine no-update state and surfaces failed post-update recovery or health validation.

USB print-server exposure checking gained behavioral regression coverage, and log-retention validation was tightened so unsafe compression/deletion ordering is rejected.

## CI and evidence model

CI coverage expanded across WAN configuration, services-start validation, firewall configuration, health-check inputs, Tailscale update/recovery behavior, restore validation, startup policy failure propagation, managed hook presence, WAN prevalidation ordering, installer syntax preflight, and USB exposure.

Documentation was also reorganized around distinct evidence classes: CI/mock, router-live, remote-client, endpoint-filtering, and future mobile telemetry. Historical SSD/reboot, DNS, printer, and encrypted-DNS evidence was reworded so each claim stayed within the scope of the source artifact.

## Endpoint filtering and offline blocklist work

A controlled endpoint-filtering methodology and evidence template were added. Zen endpoint observations, runtime evidence, and HTTPS-interception trust boundaries were documented without presenting endpoint behavior as equivalent router-side capability.

Because the Stability Gate prohibited router filtering changes, blocklist work stayed offline. Third-party upstream sources were assessed and a smaller evidence-driven candidate set was prepared for later validation instead of adopting a large aggregate list blindly.

## End-of-day state

The router baseline remained unchanged. The repository ended the session with stronger fail-fast validation, broader CI coverage, clearer recovery behavior, and tighter evidence/claim boundaries.
