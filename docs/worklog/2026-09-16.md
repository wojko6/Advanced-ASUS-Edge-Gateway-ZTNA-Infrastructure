# Engineering worklog — 2026-09-16

## Summary

This session focused on audit remediation, evidence hygiene, and clearer post-gate validation criteria while preserving the active Stability Gate.

## Transactional restore

The restore apply path was changed so affected live paths are snapshotted before mutation. Snapshot failure prevents restore from starting, while a controlled partial-apply failure triggers rollback of previously changed paths. Regression coverage was added for both snapshot failure and partial restore failure.

This remediation closed AUDIT-01.

## Exit-node NAT boundary

The audit documented that project-owned forwarding permission does not itself prove the effective WAN SNAT/MASQUERADE path for exit-node traffic. Because Tailscale runs with netfilter-mode=off and the project does not create its own exit-node SNAT/MASQUERADE rule, closure requires real runtime evidence of the platform NAT path.

This became AUDIT-02 — OPEN / GATED.

## Android/Fedora DNS datapath boundary

Earlier Android evidence was retained as a bounded historical observation, but the repository stopped treating it as proof that every Android exit-node DNS flow necessarily traverses dnsmasq/Diversion/Unbound. A controlled Fedora/Android comparison procedure was defined for after the Stability Gate.

This became AUDIT-03 — OPEN / GATED.

## Evidence sanitization and status

Deployment-specific identifiers were removed from Zen and Wi-Fi evidence, and the evidence timeline was tightened so claims match the exact source artifacts. PROJECT-STATUS.md and docs/AUDIT-REMEDIATION-2026-09-16.md were added/updated to track closed and gated findings.

The existing 2026-09-11 worklog was also merged into main during this session.

## End-of-day state

Restore safety and evidence hygiene improved without deploying router-side audit remediation. AUDIT-02 and AUDIT-03 remained intentionally deferred to post-gate validation.
