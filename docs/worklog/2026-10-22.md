# Engineering worklog — 2026-10-22

> **Scope:** [Issue #278](https://github.com/wojko6/Advanced-ASUS-Edge-Gateway-ZTNA-Infrastructure/issues/278): installer atomicity, rollback correctness and publication trust boundaries. **Evidence:** operator-reported Fedora laboratory outputs, pinned GitHub source review, assistant-side disposable synthetic checks. **Publication:** sanitized technical checkpoint, not a production acceptance or a complete record of unrelated same-day work.

## 1. Source finding and controlled laboratory baseline

- Reviewed the historical [`scripts/install.sh`](../../scripts/install.sh) against pinned source commit [`505ab768cf9d`](https://github.com/wojko6/Advanced-ASUS-Edge-Gateway-ZTNA-Infrastructure/tree/505ab768cf9d0bcf8fd34222c4df4ce3d8bac676). The in-place copy and mode-change pattern for root-executed scripts/supervisor, and delete-before-restore rollback, create identifiable integrity risks. This is a source-level finding, **not** a demonstrated failure or attack on a deployed router.
- Isolated regression stages V0.1–V0.11 reproduced partial-write and rollback hazards and exercised leafwise replacement, injected failures, inode/FD behavior, real mapped UID/GID boundaries and expected privileged-actor RED cases. Success is bounded to the tested fixtures.
- A BusyBox **1.25.1 source build with host-compatibility patches** passed the 11-scenario execution matrix following a correction to the syntax-check methodology. BusyBox 1.25.1 `sh -n -c` was found unsuitable as a safe parse-only gate in the tested build; Fedora host `/bin/sh -n` was used for parse-only checking and the BusyBox binary executed the disposable scenarios. This is **not** a firmware-identical binary.

## 2. Review-only installer prototype and negative regressions

| Stage | Operator-reported result | Evidentiary boundary |
| --- | --- | --- |
| V0.12 | Review-only source transformation and 34 synthetic checks passed; installation execution was explicitly blocked with `exit 97`. | Not an accepted patch or a production run. |
| V0.12.1 | Five expected negative regressions reproduced: directory-target `mv` nesting, absent `bin` rollback, unmanaged files, empty snapshot handling, and directory-mode drift. | PASS here means the blockers were reproduced, not fixed. |
| V0.12.2 | Revised review-only candidate: 40 local checks passed; unsafe states return HOLD rather than deleting unknown data. | Depends on `mv -T`; not firmware-compatible as tested. |
| V0.12.3 / V0.12.3b | Tested BusyBox 1.25.1 rejected `mv -T`; `mv -f` could falsely succeed by nesting a file into a target directory. Non-`bin` delete-before-copy rollback hazards reproduced. | Host-built BusyBox only; production unchanged. |
| V0.12.4 | Host C `renameat()` helper prototype and non-destructive rollback preflight passed 9/9 selftests and 38 bounded checks. | Not integrated into the firmware installer; non-`bin` automatic rollback unimplemented. |

The `renameat()` directory-FD primitive provided exact-name replacement semantics in the host tests, avoiding the directory nesting seen with `mv -f`. This does **not** establish a race-free trusted publisher, ARMv7 bootstrap or JFFS2 power-loss durability.

## 3. FD handoff and publisher-role isolation

| Stage | Operator-reported result | Security conclusion |
| --- | --- | --- |
| V0.12.5 | 8/8 selftests, 10/10 scenarios; expected late same-UID staging-mutation RED reproduced. | A verified digest and inherited FDs do not freeze mutable stage bytes; post-commit mismatch requires `COMMIT_UNCERTAIN_HOLD`. |
| V0.12.6 | 11/11 selftests, bounded PASS with expected same-publisher-UID RED. | A distinct untrusted input UID was denied writes to publisher-private staging; publisher UID and userns root remain outside the protection. |
| **V0.12.7** | **11/11 selftests; `V0127_EXIT_CODE=0`** and `PASS_BOUNDED_AUTHORITY_OWNED_STAGE_WITH_EXPECTED_SAME_AUTHORITY_RED`. | Independent Input and Requester UIDs could not modify Authority-private staging or live file in the measured window; a same-Authority-UID process did corrupt stage bytes after verification, resulting in `COMMIT_UNCERTAIN_HOLD`. |

V0.12.7 used four distinct mapped host UID/GID identities in a rootless user namespace. A negative input was rejected before staging; an approved Authority-owned private copy was published intact in the positive case. A separate controlled RED case confirmed that same-Authority-UID compromise is **not** mitigated by this DAC separation. The expected SHA-256 in the fixture was not cryptographically authenticated.

## 4. Explicit safety decision and open gates

- **Production ASUS contact:** none in the recorded Issue #278 tests. No production installer execution, JFFS/SSD mutation, service restart, deployment or active installer patch merge.
- **Issue #278:** OPEN, `DEPLOYMENT_GATE=HOLD`. Related [Issue #235](https://github.com/wojko6/Advanced-ASUS-Edge-Gateway-ZTNA-Infrastructure/issues/235) / [Draft PR #245](https://github.com/wojko6/Advanced-ASUS-Edge-Gateway-ZTNA-Infrastructure/pull/245) remain independent and unaffected.
- **Still unproven / unimplemented:** GNUton ARMv7 trusted helper bootstrap and real role assignment; authenticated stage provenance; same-Authority-UID and privileged-writer threats; safe automatic restore of `legacy`, `webui` including nested trees, configs and hooks; multi-file transaction semantics; firmware BusyBox/JFFS2 behavior and power-loss recovery.
- **Next decision:** assess practical authority-role separation on GNUton and a review-only ARMv7 helper contract while separately redesigning non-destructive non-`bin` rollback. Keep the installer inert and require distinct authorization for any real router test.
