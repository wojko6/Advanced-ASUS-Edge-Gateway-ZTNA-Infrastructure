## Problem and implemented boundary

[D's volatile ledger](V0.14.5D-SYNTHETIC-EVENT-IDENTITY-LAB.md) remembers an ID
when returning new event bytes. If a later sink fails and the caller discards
those bytes, another accept on that ledger emits nothing. Ledger acceptance is
not a durable handoff or receiver ACK.

E uses D's **pure envelope normalization**, not its precommitted ledger. It
stores every ID **together with the full canonical event payload** in one private
snapshot. There is no separate seen-ID file to commit first. Returning a receipt
can fail without making the already-published payload disappear: callers can
reopen and read the retained snapshot even when replay accepts zero new IDs.

This is a bounded **synthetic handoff model**, not a real journal source,
production transaction guarantee or receiver integration. A–D modules are
unchanged. The existing A–C spool and Alloy single-file fragment cannot consume
this new whole-snapshot format.

## File contract

| Element | Contract |
| --- | --- |
| Final file | `handoff.json`, owned regular file, exact mode 0600, one link |
| Directory | Owned 0700, cooperative nonblocking directory lock from A |
| Wrapper | Exactly `schema`, `scope`, `events`, `digest` |
| Schema | `hcc-v0145e-handoff/1` |
| Records | Canonical seven-field D events; unique IDs, sorted by ID |
| Scope | Same fixed key-scope tag on wrapper and each record |
| Capacity | 1,024 retained records and at most 512 KiB canonical snapshot |
| Input | D's strict five-field synthetic envelope, 128 rows / 64 KiB |
| Digest | SHA-256 of canonical schema/scope/events; corruption check only |
| Temporary names | Exclusive `.handoff-<32hex>.tmp`; unknown/orphan entries HOLD |

Validate the complete existing file before trusting **any** ID: exact schemas,
fixed source/component/classes, microsecond UTC time/range, ID/scope syntax,
unique sorted IDs, count/byte limits, digest and exact canonical representation.
Handle short reads and compare metadata before/after. `O_NONBLOCK|O_NOFOLLOW`
prevents following a final symlink or blocking on a named FIFO. Directory owner
and mode are rechecked. Ancestors must be trusted; root and uncooperative
same-UID mutation are outside this laboratory boundary. The digest can be
recomputed by an attacker and is explicitly **not authentication**.

## Publication and retry

1. Normalize all input envelopes in memory. Read/validate the complete current
   snapshot; an empty directory means no previous handoff, but corrupt state
   never silently resets to empty.
2. Merge canonical ID/payload pairs in a local copy. Identical record replay
   changes no stored data; a same-ID changed payload rejects the whole batch.
   A different key scope, capacity or serialization limit also rejects before
   creating a temporary file. No record is evicted or deleted.
3. Encode and validate the full prospective snapshot. Write an exclusive temp,
   enforce 0600 before publication, complete short writes and `fsync(file)`.
4. Replace the one final file with descriptor-relative `os.replace`, then
   `fsync(directory)`. Only afterward return a publication receipt. A duplicate
   retries directory sync without replacing or rewriting event bytes.
5. Ordinary pre-replace exceptions clean only the current operation's temp and
   sync that cleanup. Abrupt exits/cleanup failures may leave an orphan, which
   causes HOLD on reopen. No automatic recovery/deletion is authorized.

Each record contains its own ID and payload, so the published record set cannot
mark an ID as present while omitting its payload. The tested process-exit phases
observe a complete old/new file, or refuse progress on an orphan. A file may be
visible after a failed directory barrier without a successful receipt. These
observations are **not proof of power-loss or filesystem crash durability**.

## Observed synthetic tests

| Scenario | Observed expectation |
| --- | --- |
| Caller discards receipt, closes and reopens | All committed payload remains readable |
| Repeated/overlapping batch | Existing IDs retain data; only new records added |
| Same-ID changed payload after valid new prefix | Entire batch refused, old file byte-for-byte unchanged |
| Scope/capacity/size/schema failure | No partial new state |
| Exception before replacement | Old snapshot remains, own temp cleaned |
| Abrupt child exit after temp fsync | Old final file plus orphan; read HOLD |
| Abrupt child exit after replace | Complete new file visible; no power-loss claim |
| Abrupt child exit after directory fsync, before return | Reopen/replay finds both IDs and complete payload; no duplicate storage |
| File sync / replace / zero-write error | No success receipt, old state retained |
| Directory sync failure | No success receipt; complete new data may be visible |
| Unsafe mode, hardlink, FIFO, symlink, corrupt state | HOLD/error, no reset |

The actual child tests use bounded five-second subprocesses and `os._exit`, not
power interruption. Each case uses disposable `/tmp` directories and the public
D fixture key. Raw boot/cursor/key is not stored. IDs/classes still represent
source records, not authenticated incidents or collector executions.

## Reproduce and scope

From the HCC experiment directory, Linux/Python 3.10+:

```bash
python3 -B tools/v0145e_atomic_handoff.py --self-test
python3 -B -m unittest discover -s tests -p 'test_v0145e*.py' -v
```

`--self-test` is memory-only. `--lab` creates/removes one private temporary

## Remaining gates

- A snapshot is a complete set sorted by ID, not an append-only tailer stream,
  delivery order or receiver acknowledgement. No receiver, ACK cursor, retry
  scheduler, deletion or Loki transport exists here. No exactly-once claim.
- A consumer can read records repeatedly and cause repeated delivery attempts;
  a future delivery/ACK/retention transaction remains separate. Do not discard
  E receipts and assume delivery, or precommit D's volatile ledger before E.
- Public fixture key, unauthenticated synthetic source and unkeyed corruption
  digest do not validate real journal provenance. No host-key lifecycle.
- New versioned file/schema, no adapter or automatic migration for A–C/Alloy.
  Do not point the existing Alloy NDJSON fragment at this rewritten JSON file.
- No cold reboot, power-loss, real-filesystem recovery, workstation SELinux/ACL
  persistence or production rollback validation. All state is removed at lab exit.

**No real journal, ASUS, network, real Alloy/Loki/metrics, HCC HTTP/UI, systemd,
service configuration, production store or merge. DEPLOYMENT_GATE=HOLD.**
