## Precisely scoped change

Three additive files form an **isolated experimental integration**. No previous HCC runtime module, source reader, Caddy or Grafana service is edited:

- `tools/v06_b3b2d_cancel_guard.py` adds a separate `read_b2_with_peer(window, peer)` supervisor. The default child argv is inherited from the canonical B3B2A fixed B2 allowlist (no caller-selected PromQL, URL, IP, metric or arbitrary dates). It monitors Linux B3B2C `POLLRDHUP/HUP/ERR/NVAL` every ~50 ms while waiting for stdout, for process exit, and after validating the response. A disconnected peer aborts the source child, SIGKILLs its isolated process group, reaps it and returns sanitized `UNKNOWN`. An overall provisional **12s child lifetime**, **65,536-byte stdout cap enforced while reading**, and strict B3B2A provenance/interval validation remain in force. No worker is launched on import or from `--inspect`.
- `tools/v06_b3b2d_cancel_http_proof.py` adds a **new handler class for synthetic tests only**, not a server or listener CLI. It reuses B3B1 fixed Host/Origin/Fetch-Site + single in-flight history lock + B3B2B sanitized response/no-store. Its sole accepted `GET /api/dns-guard-history?window=1h|6h|24h|7d` may call the peer-aware supervisor only when explicitly invoked by the ephemeral test server. After a disconnected result it sends **no HTTP response**; other errors result in `UNKNOWN` and never stale success. Response headers/body are emitted at most once and the lock is released.
- `tests/test_v06_b3b2d_cancel_http_proof.py` binds an ephemeral `127.0.0.1:0` listener inside each synthetic test only. Every call to the fixed command source is intercepted and replaced by a harmless local Python child (sleep, bounded synthetic B1/B2 JSON, malformed/oversized stdout or nonzero exit). The decisive test closes an actual TCP client connection **while a synthetic guarded child is running**, asserts kill/reap, history lock release and prompt cancellation. Other tests cover one allowed GET, bad routes/methods/Origin, rejection before worker launch, concurrent 503, unknown and no stale-success fallback.

The original `v06_b3b2b_manual_http.py` remains entirely **unchanged** and is **not yet wired** to the peer-aware supervisor. Merely passing this PR's tests does **not** retrofit live B3B2B cancellation. That requires a separate, reviewed activation/integration gate.

## Acceptance and important limitations

1. Exact-head GitHub CI, then pinned non-root Fedora acceptance: targeted B3B2D Python tests, all Python regression tests, all Node regression tests, `python3 -B tools/v06_b3b2d_cancel_guard.py --inspect`. No real VictoriaMetrics source call in this stage.
2. The peer detector is Linux-specific. A write-half-close is interpreted conservatively as a disconnect. Fail-closed `UNKNOWN` is a laboratory signal, **not a DNS failure**. A client not closing its TCP connection can remain idle, so child deadline and output caps remain necessary.
3. **This does not guarantee a full HTTP end-to-end response deadline or authenticated access**, and test-induced child aborts say nothing about actual B2 behavior under load. Do not expose on WAN, LAN, Tailscale or Caddy. No systemd/autostart, scheduled reads, persistence, Grafana Email/Telegram or production router contact.
4. Next gate (B3B2E) must explicitly wire cancellation into the existing two-flag manual B3B2B route after a source-only review, rerun the full regression and only then seek separate operator authorization for **one real manual localhost 24h GET**. A 7d GET and B3C visual timeline require further approval and their own evidence.
