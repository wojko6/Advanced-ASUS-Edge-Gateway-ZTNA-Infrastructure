## Implemented result

B connects the [A supplied-metadata adapter](V0.14.6A-SUPPLIED-JOURNAL-ENVELOPE-LAB.md)
to a private disposable [E-format snapshot](V0.14.5E-ATOMIC-HANDOFF-LAB.md).
It validates the whole input and retained store, merges by event ID/full
canonical payload, and atomically replaces one `handoff.json`. Reopen/replay
retains existing events without rewriting exact duplicates. All accepted
payloads remain until test-directory cleanup; no retention deletion exists.

This is a filesystem import result, **not delivery ACK, source cursor or
authenticated journal ingestion**. A still accepts consistently fabricated
metadata. No journal reader, real key lifecycle, transport, running Alloy/Loki,
HCC endpoint or production store is connected. A and frozen A–K code/tests
remain unchanged; B is a separate module using their existing contracts.

## Policy scope and data boundaries

B supplies A with a derived 32-byte key:
`HMAC-SHA256(base_key, canonical({domain, uid, unit, transport}))`, with domain
`hcc-v0146b/synthetic-policy-key/1`, explicit expected UID, D's fixed unit and
`stdout` transport. This separates namespaces for declared policies. The
derived key is not stored or printed. Only its D-derived opaque scope/IDs
appear in E. Policy UID is not the OS account writing the temporary file.

Once events exist, changed expected UID or base key gives scope HOLD, even
for an input with no matched hints. B intentionally differs from standalone
A/E fixture scopes: existing files are not silently migrated. This namespace
binding is **not authentication or an independent rollback/loss anchor**.
The CLI base key remains public synthetic fixture material.

Within one batch, A rejects changed raw messages at the same boot/cursor.
Across calls, B compares only retained D payloads: a different private message
with the same cursor/time/hint is an exact sanitized duplicate. A test proves
this limitation. Raw messages/fingerprints, cursors and source UID are not
persisted. Events may be added with lower IDs or earlier times across batches;
the file is a retained ID set, not a source traversal/checkpoint order.

An empty/no-match first batch creates no file or policy anchor. Losing the
entire snapshot in an otherwise empty directory is indistinguishable from a
fresh store; a test shows the next call can import the events again. A valid
unkeyed checksum detects corruption, not authenticated state replacement.

## File transaction and failure semantics

1. Strictly validate options/key and all A input. Read/validate the complete
   existing E store, including on no-match/duplicate calls. Unknown/orphan
   entries and corrupt state never reset to an empty snapshot.
2. Require matching policy scope; merge full payloads by ID. Same retained ID
   with different canonical payload is HOLD. Enforce E's **1024 events /
   512 KiB**, in addition to A/D input limits, before opening a temporary file.
3. Write an exclusive descriptor-relative temporary file at mode `0600`, sync
   it, atomically replace `handoff.json`, then sync the private `0700` directory.
   Return a publication receipt only after those steps succeed.
4. Exact duplicates/no-match do not create or replace a snapshot; retry the
   directory sync barrier before returning. Ordinary pre-replace failures
   clean temporary state; abrupt exits can leave an orphan and subsequent HOLD.

The low-level API takes a trusted caller's private directory descriptor and
holds the inherited cooperative lock until it closes. Do not share one open
description across concurrent calls. Existing E owner/mode, no-follow,
nonblocking FIFO, regular-file/link and pre/post-read checks apply. This is
not protection against root or uncooperative same-UID/trusted-code mutation.
The CLI accepts no path and supplies only its own disposable `/tmp` directory.

| Interruption | Observed process/filesystem result |
| --- | --- |
| Ordinary exception after temp-file sync, before replace | Old snapshot preserved; temporary file cleaned |
| Actual child exit before replace | Old complete snapshot plus orphan temp; next reader HOLD |
| Actual child exit after replace, before directory sync | Complete new snapshot visible on this filesystem; next replay deduplicates after retrying the barrier |
| Actual child exit after directory sync, before result | Committed file retained; caller received no receipt; replay deduplicates |
| File sync / zero-write / replace failure | No success receipt; old data retained in the tested pre-replace paths |
| Directory sync failure after replace | No success receipt; new file may be visible; explicit uncertainty |

The three abrupt-exit tests run separate Python children and reopen fresh
descriptors. They do not simulate physical power loss, storage-controller
failure or a reboot. There is no hard whole-operation filesystem deadline,
automatic orphan repair, retry scheduler or event deletion.

## Reproduce and validation

From the HCC experiment directory, Linux/Python 3.10+:

```bash
python3 -B tools/v0146b_disposable_import.py --self-test
python3 -B -m unittest discover -s tests -p 'test_v0146b*.py' -v
python3 -B tools/v0146b_disposable_import.py --lab
```

Self-test is pure memory with file/socket/process creation denied. Lab writes
only its newly created private test store, reopens it, checks replay, simulates
a lost result after commit and removes the entire disposable directory. It
prints success only after cleanup succeeds. Neither mode accepts stdin,
source/store path, UID, key or endpoint input. No sudo or service action.
