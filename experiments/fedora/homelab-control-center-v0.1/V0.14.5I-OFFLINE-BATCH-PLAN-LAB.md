## Result and boundary

[H](V0.14.5H-OFFLINE-LOKI-REQUEST-LAB.md) deliberately rejects a whole snapshot
larger than 16 records. I prepares several bounded H request bodies from one
completely validated [E snapshot](V0.14.5E-ATOMIC-HANDOFF-LAB.md), excluding IDs
with consistent **declared synthetic F ACKs**. Every pending record appears
exactly once in the returned plan; that is a plan-coverage property, not
exactly-once delivery.

The plan binds the exact source and declared ACK bytes. `require_current`
rebuilds the complete plan and rejects changed input or altered request bodies,
membership/checksum/metadata. The caller must supply freshly obtained bytes;
this pure function does not read/lock live files or prevent later changes.

No requests are sent, no real ACK is observed, and no checkpoint/receiver
state is advanced. I does not inspect G's receiver files. F's serialized fixture
ACKs are **not actual Loki receipts** or proof of G receiver durability.
Consistent forged source/ACK bytes can produce an apparently completed plan;
that explicit negative case is tested. No source authentication is added.

## Input and output

| Element | Contract |
| --- | --- |
| Source | Exact canonical E snapshot bytes; whole 1–1,024-event / 512 KiB validation |
| ACK basis | Exact F state bytes, up to 1,024 pairs / 256 KiB; or explicit `None` for no declared ACKs |
| ACK consistency | Matching scope and every saved ID/full-payload hash present in source |
| Request bodies | Existing H encoder, at most 16 records / 64 KiB each |
| Plan budget | At most 64 requests / 1 MiB of body bytes in total; laboratory limits |
| Order | Global timestamp then event ID, including ties across request boundaries |
| Result | Frozen in-memory scope, source/ACK SHA-256, counts and tuple of H requests |
| Empty result | All source records declared ACKed → no requests, after full validation |

`None` is an explicit caller declaration, never a fallback for corrupt/empty/
missing-file errors. It differs from a serialized empty ACK file in the frozen
plan fingerprint even though both initially select all records. Digests are
checksums, not authentication, durable anchors or receipts. This module accepts
bytes, not filesystem paths or a journal source.

## Planning steps

1. Validate the entire source before any request construction. Decode complete
   ACK state when supplied. Unknown ACK ID, changed payload hash or scope HOLD
   before building a request; invalid trailing source records are not hidden.
2. Select IDs absent from the declared ACK set. This is set-based selection,
   not an acknowledged prefix or last-ID watermark. A newly appended lower ID
   remains pending when the caller explicitly builds a new plan.
3. Sort pending records globally by exact integer timestamp then ID. Check the
   total request-count cap before constructing any request.
4. Divide into consecutive groups of at most 16. Rewrap each group in canonical
   E ID order for H validation; H restores time/ID order in the request body.
   This does not modify A–H or F/G's delivery ordering.
5. Enforce every H bound and total body budget. An encoder/budget error returns
   no partial plan. No truncation, prefix publication, file or progress mutation.
6. Return immutable request bytes and exact-input checksums. On reuse, recompute
   all input checks and request content; an append, ACK change, `None`/empty-file
   transition or altered plan HOLD rather than silently mixing versions.

Reuse checks require exact immutable field types before value comparison:
boolean/float counters and mutable `bytearray` bodies HOLD. Otherwise Python's
value equality can accept `True == 1` or `bytearray(body) == body`. The
prepublication failing regression and correction are retained in the worklog.

Recomputation verifies consistency with the **provided** bytes only. Reusing
old bytes cannot detect live changes, and a change after the check remains a
future transport/locking concern. Plans are not persisted or signed. Discarding
a plan and rebuilding against lost/forged state does not provide rollback/loss
detection; G's paired-state-loss limitation remains.
