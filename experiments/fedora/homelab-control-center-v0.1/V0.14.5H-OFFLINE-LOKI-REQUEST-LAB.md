## Result and boundary

H converts one completely validated [E snapshot](V0.14.5E-ATOMIC-HANDOFF-LAB.md)
to a bounded JSON request body in memory. Exact source microseconds become
decimal integer nanoseconds **encoded as strings**. Full canonical D-format
event lines retain their ID/scope; the request has only two fixed stream labels.
Sorting by timestamp then event ID preserves distinct same-time records.

This is a formatter, not an HTTP client, receiver, ACK protocol, batch scheduler
or proof of Loki acceptance. It does not read/change [F](V0.14.5F-SYNTHETIC-DELIVERY-ACK-LAB.md)
ACK state or [G](V0.14.5G-DISPOSABLE-FILE-RECEIVER-LAB.md) receiver files. G's
paired-state-loss limitation remains. No file input/output, network, subprocess,
real journal, real key store, Alloy config or service access exists in H.

## External contract consulted

Reviewed the public **latest** Grafana documentation on **2026-10-30**:

- [Loki HTTP API — ingest logs](https://grafana.com/docs/loki/latest/reference/loki-http-api/#ingest-logs):
  JSON uses `streams`, a stream label map and timestamp/log-line pairs;
  push timestamps must be strings. The declared path is `/loki/api/v1/push`
  with `Content-Type: application/json`.
- [Loki label guidance](https://grafana.com/docs/loki/latest/get-started/labels/bp-labels/):
  prefer bounded labels rather than ephemeral identifiers. H keeps event IDs,
  key scope, time and class inside the JSON log line, not stream labels.

These references describe an encoding shape. They are not validation against
the operator's installed Loki build/config, its time windows or ingestion
limits. Future transport/status/authentication semantics remain separate.

## Mapping and limits

| Input / property | Request representation |
| --- | --- |
| Full E wrapper | Validated entirely, including canonical form/digest/schema before H's record limit |
| Event `time` | Six-fraction UTC → integer nanoseconds string; source precision remains microseconds |
| Full canonical event | JSON string in the second value position; original event bytes survive unescaping |
| Stream labels | Exactly `component=dns-guard-collector`, `source=synthetic-unit-envelope` |
| Request order | Increasing timestamp, then lexicographic event ID for equal timestamps |
| Sidecar result | Immutable body bytes, scope, IDs in request order and body SHA-256 |

H accepts **1–16 records** and at most **64 KiB** of encoded body. E retains its
independent 1,024-event / 512 KiB input bounds. These are laboratory limits,
not configured Loki server limits. A valid snapshot with 17 records is rejected
as a whole; no partial request, truncation, pagination or pending-ACK filtering.
A corrupt late record is rejected before a count-limit response can hide it.

Only exact E snapshot bytes are accepted by `build_request`; no path, raw
journal/envelope, legacy A–C rows or arbitrary labels. Extra/private fields,
mixed scope, changed digest, duplicate/unsorted IDs or noncanonical input HOLD.
Input ID order is verified before request time sorting. A–G source modules and
delivery ordering remain unchanged.

Time conversion uses days/seconds/microseconds integer arithmetic, without a
float timestamp or host-clock fallback. The source contract allows years
2000–2100 with exactly six fractional digits and `Z`; malformed dates, leap
seconds, alternate offsets or changed precision HOLD. Boundary-year tests are
numeric conversion tests, not evidence that Loki would ingest those dates.

The SHA-256 sidecar is a checksum, not authentication or a receipt. Recomputed
valid-looking source files with invented IDs can encode successfully; H does
not authenticate source provenance. Neither request encoding nor formatting
an existing record advances progress or establishes exactly-once delivery.
The formatter does not interpret any HTTP response or F/G fixture ACK.

## Reproduce and validation

From the HCC experiment directory, Linux/Python 3.10+:

```bash
python3 -B tools/v0145h_loki_request.py --self-test
python3 -B -m unittest discover -s tests -p 'test_v0145h*.py' -v
python3 -B tools/v0145h_loki_request.py --lab
```

Both CLI modes and H tests use **synthetic memory only**. No temp trees are
created and no paths, stdin, files, URLs, credentials or client settings are
accepted. CLI output reports counts/markers, not body bytes, record IDs or
scope. I/O-denial tests cover files, sockets and subprocesses in both modes.

Python **456** and JavaScript **55**. Observed runs/limits are recorded in the
