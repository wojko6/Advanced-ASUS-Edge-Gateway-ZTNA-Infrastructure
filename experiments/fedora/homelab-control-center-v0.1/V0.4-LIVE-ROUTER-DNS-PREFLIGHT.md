## Contract and limitations

- `OK / ONE_DNS_PROBE_SUCCEEDED`: exactly one currently fresh `internet_dns` sample succeeded; the literal UI calls it **one test**.
- `DEGRADED / ONE_DNS_PROBE_FAILED`: fresh one-probe failure, never automatically **router DOWN**.
- `STALE`: sample older than 120s (**provisional threshold**, not calibrated against measured live scrape cadence) and success/failure suppressed.
- `UNKNOWN`: missing/duplicate count, malformed, partial, inconsistent or unavailable source, invalid clock/value, or no prior sample. No stale-last-good display.
- The 3 reads are sequential **not atomic**; race across scrape boundaries is possible. The aggregate parser removes raw labels/targets, so one current count only attests candidate cardinality at that query instant. This is not an independent exact-source fingerprint or certification of the current deployed scrape config.
- API returns only fixed, sanitized fields, no router IP, client identity, query log, credential, raw series or arbitrary metric name.
- HTTPS alias `https://control.home.arpa/` may forward to this candidate **only** when the operator explicitly starts the manual backend on port 8788; this source change does not alter Caddy or host configuration.
- V0.1/V0.2/V0.3 files and working processes remain unchanged by checking in V0.4 source.
- Black Box #304, real service-wide DNS/Unbound/Tailscale health, installation, autostart and remote access are out of scope.
