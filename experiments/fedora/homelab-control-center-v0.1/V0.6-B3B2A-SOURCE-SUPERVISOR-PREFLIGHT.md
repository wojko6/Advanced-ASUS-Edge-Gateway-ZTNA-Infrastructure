## Narrow scope

- `tools/v06_b3b2_source_supervisor.py`: an import-only source guard function; no active read from importing the module and `--inspect` only prints the contract. There is **no public CLI command for fetching history** in this stage. The function, if explicitly invoked by future approved code, runs the existing **fixed B2** CLI with `--read-local --window 1h|6h|24h|7d` as a single child, never a shell or caller-selected PromQL, IP, URL, label, time range or executable.
- It confines only the child subprocess lifecycle, with a provisional **12-second elapsed deadline** encompassing child creation and stdout consumption, and a **64 KiB stdout limit enforced while streaming**. On timeout, bad JSON, oversized output or failed exit, it sends SIGKILL to the child's new process group, reaps the worker, discards all accumulated evidence, and returns neutral `UNKNOWN`. Stderr is discarded; no raw source identities are sent to the view.
- It validates fixed B1/B2 schema and source identifiers, window, ISO UTC timestamps, bounded gaps/segments and numeric consistency, and outputs only allowlisted/sanitized fields. The independent B3A browser projection performs its own stricter cross-gap/segment parity before any display.
- These limits are **provisional** and this is **not a complete HTTP request time bound or production SLO**. The future B3B2B adapter must also bound request/response size, concurrent handlers, source-call exclusivity, client disconnect behavior, total request delivery and cancellation. Do not run this reader behind HCC without an additional audited HTTP integration.
- The source experiment B3B1 server on port 8790 still returns **MOCK_ONLY UNKNOWN** and is not modified. The fixed V0.5 October 27 archive, port 8788, three LIVE panels and opt-in DEMO remain unchanged.

## Test gates

- New `tests/test_v06_b3b2_source_supervisor.py` uses synthetic responses and *substituted synthetic child commands*; it never invokes default B2 with real VM access. It checks early output bounding, deadlines, nonzero exits, malformed/duplicate JSON, sanitized allowlist and no stale success. An ephemeral synthetic child process may be started, but no persistent listener or daemon is used.
- Run exact-head GitHub CI and pinned non-root Fedora Python regression and Node suite. Audit source `--inspect`; all tests must use the synthetic command injection only. `DEPLOYMENT_GATE=HOLD` even after passing.
- Optional B3B2B real-source manual read requires a separately reviewed and explicitly authorized opt-in action; no live HCC history UI, polling, notifications or source writes may be added implicitly.

## Security limitations for review

- The 12-second limit cannot prove successful real-source response during slow periods; fail-closed UNKNOWN is required and does not imply a DNS failure.
- A successful 7d CLI measured 0.138 seconds on one operator run, which is **not** a guaranteed worst-case bound or a basis for changing production timeout settings.
- Timezone is strict UTC in B2 data and converted to Europe/Warsaw **with offset** only by B3A's view; missing telemetry is never automatic DNS outage or a confirmed router power-off.
- No systemd/cron, autostart, Caddy/Grafana, ASUS contact by HCC, Pi-hole/Unbound, DNS Guard changes, persistent stores, external exposure, Email/Telegram or alert routing.
