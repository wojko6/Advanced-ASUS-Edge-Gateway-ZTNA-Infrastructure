## Scope and inheritance

- Source baseline: B1 offline coverage model merged via [PR #329](https://github.com/wojko6/Advanced-ASUS-Edge-Gateway-ZTNA-Infrastructure/pull/329), merge commit `6b0d6fc5c1084951d0edb922a57b4f8e5fe931db`. V0.5 fixed Oct-27 archive is not changed.
- New `tools/v06_history_source.py` is a **separate manual preflight reader**, not an HCC route, service or scheduled collector. Without explicit `--read-local --window 1h|6h|24h|7d` CLI it cannot contact VictoriaMetrics. `--inspect` only prints limits and performs no HTTP.
- Exactly **seven approved DNS Guard metric names**, requested through seven sequential fixed `GET /api/v1/export` requests to **127.0.0.1:8428 only**. No dynamic PromQL, arbitrary timestamps, hostname, labels or query scope. Window end is captured once from an aware UTC clock; all seven requests share the same start/end. No redirects or proxy routing.
- Raw export is bounded to **512 KiB per series**, **64 chunks**, **200 rows/chunk**, **12,000 samples per series**, **32 KiB per JSON line**, and **5-second socket-operation timeout per HTTPConnection**. A 5-second socket timeout **is not a total request deadline**; the seven sequential reads are not a guaranteed <35-second SLO. Do not attach to a browser UI until end-to-end time budgets are separately measured and resolved.
- Strict NDJSON/CSV-independent parse: exact `metric` object with only `__name__`, no duplicate JSON keys, exactly timestamps/values arrays, finite integral values, no duplicates or out-of-order timestamps across chunks, no silently sorted source evidence. Refuse non-200, oversize, missing, extra or contradictory replies.
- Feed the seven validated in-memory series into B1 `coverage.analyze`. Return **only sanitized** window times, sample counts, observed telemetry segments, explicit leading/internal/trailing missing-data windows, and `UNKNOWN` for unsupported or conflicting source. No raw row dump, personal identifiers, source labels, router logs, or individual DNS queries. Do not interpret "no telemetry" as DNS outage or infer operator power-off from samples.

## Operator observations / known boundaries

The operator confirmed the router and Fedora laptop are **not routinely powered for all 24 hours**. An Oct-29 source audit found **642 observations per metric, 0 ms seven-series timestamp mismatch** for a 24-hour interval; this is *not* proof of continuous DNS uptime. The earlier 7-day count was 4963 samples in a single metric **at a different evaluation time**. B2 does **not** claim that seven-day raw time alignment or complete historical coverage has yet been verified.
