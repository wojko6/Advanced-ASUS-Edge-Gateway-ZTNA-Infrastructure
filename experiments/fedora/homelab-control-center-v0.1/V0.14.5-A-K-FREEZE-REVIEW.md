## Findings fixed before freeze

### FZ-01 — non-finite manual-report numbers

The imported V0.14 report parser accepted `nan` in `DURATION_SECONDS` and
`RESIDUAL_NOT_MATCHED_SECONDS`: ordinary comparisons against NaN do not reject
it, allowing a report to render invalid numeric values. Reproduced both
acceptances. The new regression failed for those two subcases before the fix.

Added a finite-number check for duration, overlap percentage and residual
before range/consistency checks. The new case exercises `nan`, `inf` and
`-inf` in all three fields. Legacy V0.14 now has **7 cases**, up from 6;
the full HCC total rises from 541 to **542**. No A–K schema/module change.

### FZ-02 — HTTP test assumed response implied lock release

The first full closing regression ran **542 tests in 33.525 s**, with one
failure in `test_inflight_second_read_is_503_invalid_unrelated_route_is_403`:
`history_lock.locked()` was still true immediately after the client thread
received its response. This is a separate local failed observation, retained
in the [worklog](../../../docs/worklog/2026-10-30.md).

The existing handler sends its response before its `finally` releases the
lock. The earlier event-gated regression in `test_v06_b3b2b_manual_http.py`
already demonstrates this ordering with the same handler. Added a bounded
real-lock acquire/release barrier to B3B2E assertions and sequential reads,
plus explicit expected-200 checks before decoding response bodies. A leaked
lock still fails after one second. The 503/403 checks remain; no HTTP retry,
new sleep, skip or runtime-handler/source-guard relaxation was introduced.
B3B2E's existing **8 cases** pass after the correction; no new case count.

No other blocking defect was identified within the declared laboratory model
in this review. That observation does not establish exhaustive input, host,
transport or crash/power-loss safety.
