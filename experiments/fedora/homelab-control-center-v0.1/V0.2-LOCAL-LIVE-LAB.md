## What changed compared with V0.1

The default `run-lab.sh --serve` remains the **purely offline V0.1 demo**: port 8787, CSP `connect-src 'none'`, six fictional scenarios, four existing pages and zero API reads.

An **additional, explicitly invoked** V0.2 demonstration reuses the existing UI files but starts a separate **non-root** loopback HTTP listener on `127.0.0.1:8788`. It adds one clearly marked, real VictoriaMetrics **aggregate** tile *above* the fictional service/incident/Recovery widgets. Those fictional widgets stay labelled `DEMO`; no source mixing and no Loki log access.

No application/service install, root privileges, scheduled timer, router contact, new Grafana datasource, modification of network listeners or reverse proxy, alert-policy or DNS change is required.

## Read-only data contract

On each page load and each explicit `Odśwież pomiar` click, the local browser GETs only `/api/summary` from its own origin. The application server makes **exactly three sequential fixed GETs** to **127.0.0.1:8428** (VictoriaMetrics):

- `count(up)` — count of current scrape-target series;
- `sum(up)` — aggregate sum of successful scrape-target series;
- `max(time() - timestamp(up))` — oldest sample age among the returned series.

**No raw metric labels, client identity, router address, raw Loki logs, PromQL supplied by the browser, or secret-bearing API responses are returned.** VM query response is capped at 8192 bytes per request with a two-second timeout, and the result is validated against exact schema, single unlabeled aggregate, plausible timestamp and numeric limits. Unexpected API status/shape or connection failure returns `UNKNOWN` without preserving the old green status. Requests are close in time but are **not an atomic snapshot**.

The tile states mean **scrape-target observations**, *not* complete service availability:

| State | Condition | Caveat |
| --- | --- | --- |
| `OK` | `up == total` and oldest `up` sample at most 120 s old | Does not prove that applications/DNS/alerts function correctly |
| `DEGRADED` | Some but not all scrape targets UP, fresh observations | No target identities exported |
| `DOWN` | Zero healthy of a positive total, fresh observations | Targets down, not necessarily host offline |
| `STALE` | Oldest observed `up` sample age over provisional 120 s | Never persist an old green status |
| `UNKNOWN` | API down, malformed/empty/inconsistent response, missing evidence | No green fallback |

**120 seconds is a provisional laboratory freshness gate**, four times the historically documented 30-second exporter/scrape interval and greater than the operator-observed maximum age ~29.7 seconds on October 25. It is **not** a universal TTL, nor proof that current scrape settings still match the historical config. Future calibration requires a separate approved cadence audit. There is **no background polling**; UI summary expires after its short TTL.

## How to test locally, *after reviewing the source*

Prerequisites: Fedora with standard Python 3 and a loopback-only VictoriaMetrics endpoint at `127.0.0.1:8428` (already observed in bounded operator preflight). Node.js is optional for running tests.

```bash
# In the reviewed source directory containing the original V0.1 app and V0.2 additions:
node --test tests/*.mjs
python3 -B -m unittest discover -s tests -p 'test_*.py' -v
bash -n tools/run-live-lab.sh

# Manual opt-in: non-root, foreground, no systemd unit or scheduled task
bash tools/run-live-lab.sh --serve-readonly
# Open http://127.0.0.1:8788/ locally. Ctrl+C to stop.
```

No need for `sudo`, `systemctl`, `tailscale`, a router shell or any administrative credential. Do **not** expose port 8788 on LAN/WAN/Tailscale, publish the panel through Caddy, or run it as a permanent service. The local HTTP endpoint is unauthenticated and only appropriate for this operator-local lab.

If VictoriaMetrics is absent/blocked, the live tile shows `UNKNOWN`. A separate V0.1 demo on port 8787 remains unaffected. The V0.2 server does not expose arbitrary files: six explicitly allowlisted static assets plus read-only `/api/summary`; POST/PUT/PATCH/DELETE are forbidden; it rejects unexpected Host headers. HTTP is only loopback, no secrets in browser, files or URLs. API data are intentionally coarse.

## V0.2 failure simulation — isolated fixture-only server (2026-10-25)

The operator's first real 7/7 UI screenshot is a successful positive-path smoke only. To test *failure handling without shutting down VictoriaMetrics*, this follow-up adds a wholly **synthetic** server on a **separate** loopback port **8789**. Its summary provider is explicitly replaced with deterministic fixture data. It makes **no VictoriaMetrics, Loki or ASUS HTTP requests**, even if port 8428 is available. The fixture page has a distinctive SIMULATION banner; the real V0.2 server and the original V0.1 demo are independent.

Run fixture-only regression tests, without contacting any services:

```bash
python3 -B tools/v02_fixture_server.py --self-test
python3 -B -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.mjs
```

Optionally view one deliberate failure state in the browser (no `sudo`; in a separate terminal, foreground only):

```bash
python3 -B tools/v02_fixture_server.py --serve-fixture --case partial
# Open http://127.0.0.1:8789/ then Ctrl+C to stop.
```

Change `partial` to `down`, `stale`, `unavailable`, `expired` or `ok` **only after stopping the previous fixture server**; each run chooses a fixed synthetic response. In the special `expired` case, the server sends an old nominally green snapshot and the browser must convert it into `STALE` — never continue showing green. `stale` represents old source samples; `unavailable` represents an unreachable hypothetical datasource. No production faults are induced or recovered in these tests.

The V0.2 hybrid quality-of-data callout now distinguishes the real local aggregate VictoriaMetrics reader from DEMO cards. The V0.1 pure offline view retains its original warning and never contacts local metrics.
