## Motivation

The existing V0.3 lab correctly separates two live local-VictoriaMetrics panels
from fictional service, incident and recovery fixtures. However, on first load,
a user could still see green `OK` service badges, green fixture counters and
green synthetic incident markers. A single global disclaimer did not remove the
risk of mistaking these artificial successes for observed service health.

## UI-only change

- **Opt-in by default**: On `index-v03.html` only, fixture counters, service
  cards, the incident timeline and Recovery data are **not rendered at all**
  until the operator clicks **Pokaż scenariusze DEMO**. The scenario picker is
  hidden until that action.
- The operator can click **Ukryj scenariusze DEMO** to remove all synthetic
  cards immediately. Navigation between pages does not silently re-enable the
  fixtures.
- When enabled, every fictional service badge reads `STATUS · DEMO`, every
  fictional summary metric label includes `DEMO`, and fixture cards display a
  simulation annotation. The CSS uses subdued neutral colors for synthetic
  badges, counters and timeline markers even when the sample is `OK`.
- The two existing real read-only panels and their independent freshness,
  `UNKNOWN` / `STALE` fail-closed behavior are not changed.
- `app.mjs` and `styles.css` are shared with V0.1/V0.2; all new behavior
  and styling is guarded by the **V0.3-only** `data-demo-gate="opt-in"`
  marker and `hcc-v03` class. Legacy pages keep their original demo display.

## Security and operating boundary

No new API call, permission, endpoint, dependency, data source, listener,
automatic polling, credential, remote access or state-changing action was
introduced. This is only a source-level front-end improvement for the
existing manually run `127.0.0.1:8788` laboratory server and
`https://control.home.arpa/` Fedora-only alias. The V0.3 running browser
does **not** update automatically when this source is committed or merged.

The UI still does not prove DNS resolution, service health beyond the reported
metrics, or any real Recovery state. Neither the CSS appearance nor the label
`2 LIVE` authorizes auto-start, service install, network exposure,
Caddy reload, ASUS access, or a router/DNS change.

## Test plan / evidence gate

From the isolated lab root:

```bash
node --test tests/*.mjs
PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest discover -s tests -p 'test_*.py' -v
```

The new `tests/test_v03_demo_opt_in.mjs` exercises a minimal synthetic DOM:
fixture-free initial render, explicit opt-in, visible DEMO labels, navigation,
immediate hide, and unchanged legacy V0.1/V0.2 rendering. Static assertions
verify scoped neutral CSS, accessible toggle attributes and unchanged live
sections. This is **not** a substitute for a real browser test.

Operator-only optional smoke (no scripts/restarts added): open the already
running V0.3 lab in Brave and confirm that the two LIVE panels remain at
the top; no green fixture counts/services appear until the operator clicks
the DEMO toggle; every exposed synthetic `OK` badge is neutral and
explicitly marked `DEMO`; hiding DEMO removes the fixtures again.
Repeat on `Usługi`, `Incydenty`, and `Recovery`. Do not claim browser
acceptance unless this operator smoke has actually been performed.

## Rollback

Revert these source-only changes or manually use the previously reviewed V0.3
