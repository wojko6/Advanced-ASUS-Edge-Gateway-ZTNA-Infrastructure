## Result and boundary

K runs a selected initial part of an [I plan](V0.14.5I-OFFLINE-BATCH-PLAN-LAB.md)
through sequential [J owned-fixture exchanges](V0.14.5J-OWNED-LOOPBACK-EXCHANGE-LAB.md).
It rechecks supplied source/ACK bytes before each selected request and stops
at the first rejected exchange, state error or cleanup failure. Every peer
closes before the next state callback. No retry or following request after
failure; an explicit budget leaves the rest of the plan uninvoked.

Each request gets its own ephemeral numeric IPv4 peer and bounded client.
These are separate volatile fixtures, not one persistent Loki receiver.
Matched fixture results are **not receipts or a resume cursor**. All 33 records
remain pending and the two declared synthetic ACKs remain unchanged even when
the three lab exchanges match. A new explicit run starts at request zero again
and can replay earlier requests; no automatic continuation/progress exists.

## Scope and budgets

| Property | Contract |
| --- | --- |
| Selected prefix | At most four requests, starting at index zero; default limit three |
| Body budget | At most 256 KiB for selected bodies; H retains 16 records / 64 KiB per body |
| Full plan | Complete I source/declared-ACK recomputation; no unchecked tail |
| State provider | Trusted zero-argument callback returning exact `(source_bytes, ack_bytes_or_None)` |
| State checks | Initially and before each subsequent selected request, after previous peer closes |
| Response scripts | Entire selected script validated before any listener or client starts |
| Exchange | Existing J owned IPv4 peer, one bounded child and no retries/redirects |
| Result | Counts, stop index/phase and original-plan pending count; no body/ID/token or ACK |

There is **no run-wide hard wall-clock deadline**. The request-count/body caps
bound work selection; J's per-child communication/reap bounds remain unchanged.
State callbacks, process creation, OS scheduling and live file locks are not
provided or timed by K. Callers must supply fresh bytes; an old consistent
pair can hide live changes, and later changes remain possible after checks.
This is trusted test code, not a malicious-callback or hostile-peer sandbox.

K accepts no endpoint or runtime budget CLI option. Its shipped callback uses
synthetic memory only. A–J Python modules, HTTP guards and the inactive Alloy
fragment remain unchanged. No files or persistent source/ACK/receiver store
are read or updated by K's lab.

## Execution and report semantics

1. Validate limit/provider, obtain initial state and run I's strict complete
   plan verification. Invalid initial state/configuration raises HOLD before
   any network. Enforce selected-body budget and prevalidate every J reply.
2. For each selected request, revalidate callback bytes before opening that
   request's own fixture. No state callback after an error and no next listener.
3. Invoke J once for that index. Require its exact fixture-result marker, then
   complete context cleanup **before** adding a matched-exchange count.
4. Ordinary state/exchange/cleanup errors stop the run and return
   `HOLD_PREFIX_STOPPED`. Reports contain fixed phase names, not private error
   text. Cancellation (`KeyboardInterrupt`/`SystemExit`) propagates after current
   context cleanup rather than being converted into a successful report.
5. Return `PREFIX_MATCHED_OWNED_FIXTURES_ONLY` when all selected calls match, or
   `NO_PENDING_REQUESTS` for a fully validated declared-ACK-complete plan.
   Neither result changes queue state or proves actual receipt.

`send_calls` counts invocations of J, not guaranteed wire sends. `observed_posts`
counts the owned peers' observed POSTs. A failed call may send no bytes or may
already have reached the peer. `uninvoked_requests` includes all plan requests
whose J call was not invoked, including those outside the selected prefix.
`plan_pending_records` always describes the original frozen plan, not a newly
queried live queue. Matched counts are retained only for fixture bookkeeping.

| Scenario | Result / behavior |
| --- | --- |
| Three lab requests match | Three calls/POSTs/matches, all peers closed; 33 pending / two declared ACKs unchanged |
| Limit one on a three-request plan | One match; two requests explicitly uninvoked |
| Limit four on a five-request plan | Four matches; fifth request never invoked |
| Second response 500 | HOLD at index 1; first match retained, second attempted, third peer never opened |
| ACK/source drift before second request | HOLD in `STATE_REVALIDATION`; only first J call/peer |
| Cleanup error after a positive reply | HOLD; that exchange is not counted as matched |
| Second peer stalls | J deadline/reap closes clients/current peer; third never opens |
| State provider or exchange cancellation | Propagate cancellation; no next request |
| Invalid final script entry | Refuse whole setup before any network |

```bash
python3 -B tools/v0145k_prefix_exchange.py --self-test
```
