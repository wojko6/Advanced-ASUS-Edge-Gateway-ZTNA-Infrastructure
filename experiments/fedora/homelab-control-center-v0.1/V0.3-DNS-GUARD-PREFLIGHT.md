## Why this is the first V0.3 change

The V0.2 browser has **one** live datasource: a label-free `up` scrape-target aggregate from a local VictoriaMetrics process. The other service/incident/recovery tiles are still DEMO. To replace them responsibly, we first need **positive, fresh, internally consistent evidence** from each source. Do not infer DNS Guard health from `up`, historical notes, a successful exporter unit test, or a healthy control-panel HTTP response.

Existing code [`scripts/dns-guard-metrics.sh`](../../../scripts/dns-guard-metrics.sh) imports a bounded set of router-derived numerical values into **local VictoriaMetrics**. This PR does **not** call that script, SSH to ASUS, change its schedule, restart the metrics service, or modify the original V0.2 server.

The new file `tools/v03_dns_guard_probe.py` has **no network access unless the non-root operator explicitly passes** `--probe-local-vm`. Its network destination and query names are fixed in source, with no environment/url/path override or shell command execution.

## Strict six-metric contract

The probe requests six *literal* VictoriaMetrics instant selectors (not browser-supplied PromQL), sequentially on **127.0.0.1:8428**:

| Metric | Meaning, as exported | Guard |
| --- | --- | --- |
| `asus_edge_dns_guard_collection_timestamp_seconds` | Fedora exporter collection time | mandatory bounded fresh collection |
| `asus_edge_dns_guard_state_valid` | Router-reported DNS Guard mode valid | must equal 1 for positive classification |
| `asus_edge_dns_guard_mode_local` | Router currently reports LOCAL mode | 0/1 only |
| `asus_edge_dns_guard_mode_bootstrap` | Router currently reports BOOTSTRAP mode | 0/1 only; exactly one mode must be set |
| `asus_edge_dns_guard_breakglass_active` | Break-glass flag state | 0/1 only; 1 forces DEGRADED |
| `asus_edge_dns_guard_watchdog_present` | Watchdog entry observed by exporter | 0/1 only; 0 forces DEGRADED |

Each reply must contain **exactly one** series with the expected `__name__` and **no labels** (any unexpected instance/job/host labels or duplicate series fail closed), a plausible sample evaluation timestamp, an integer-like positive value where required and a bounded reply size. No raw label values, router addresses, raw metric replies, command output or credentials are ever included in the output.

**The six sequential instants are not atomic.** The provisional freshness cutoff is **180 s since exporter collection**, not 180 s since the VictoriaMetrics query. It is a *laboratory threshold only*, not a validated production cadence. The timestamp is the exporter's collection time, not proof of the underlying NTP/DNS queries.

## Possible results (telemetry only)

- `OK / LOCAL_MODE_REPORTED`: recent, internally consistent sample reports LOCAL, watchdog present, break-glass off, valid mode. **Does not prove actual Unbound/Pi-hole/DNS query availability.**
- `DEGRADED / BOOTSTRAP_MODE`: fresh, valid sample reports BOOTSTRAP; fallback can be expected for recovery and does not alone imply outage.
- `DEGRADED / BREAKGLASS_ACTIVE` or `WATCHDOG_NOT_PRESENT`: explicit risk signal from fresh telemetry.
- `STALE / COLLECTION_TOO_OLD`: collection is too old; do not keep an old green state.
- `UNKNOWN`: missing / duplicated / extra-labeled / malformed metrics; clock skew; contradictory flags; invalid state; VictoriaMetrics unavailable. Never manufacture a healthy result.

This intentionally does **not** provide a host health endpoint, aggregate incident feed, port scanner, router connectivity test, or a production alert recommendation.

## How to test after reviewing the branch

From the repository's `experiments/fedora/homelab-control-center-v0.1` directory:

```bash
# Fixture-only unit tests, no real metric source:
PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest discover -s tests -p 'test_*.py' -v
node --test tests/*.mjs

# Print the fixed contract WITHOUT a network request:
python3 -B tools/v03_dns_guard_probe.py --show-contract

# Separate opt-in read-only inspection; only local VictoriaMetrics:
python3 -B tools/v03_dns_guard_probe.py --probe-local-vm
```

`--probe-local-vm` runs exactly six fixed localhost HTTP GETs, with 2-second timeouts and 8192-byte caps, then prints a **sanitized** JSON snapshot. It refuses root, does not write to `/etc`, and does not communicate with ASUS, Pi-hole or Loki directly. If any required metric is unavailable, an `UNKNOWN` result is the **correct** outcome; collect diagnostic evidence using *another reviewed, explicitly authorized local read-only step* rather than widening this script's privileges.
