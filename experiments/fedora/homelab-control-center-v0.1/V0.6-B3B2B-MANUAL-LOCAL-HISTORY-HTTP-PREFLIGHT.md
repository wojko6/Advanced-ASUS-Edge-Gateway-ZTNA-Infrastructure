## Precisely what this PR proposes

- New **alternative** `tools/v06_b3b2b_manual_http.py`. Merely importing it or running `--inspect` has no listener, VM read, router connection, persistent state or network activity.
- A future **explicit operator action**, not part of the automated tests, could run this as a non-root foreground process with **both** `--serve-manual-local-history --ack-local-vm-read`. It would bind **only** `127.0.0.1:8791` (not HCC V0.5 port 8788 or the B3B1 mock port 8790). No Caddy route, Tailscale/LAN/WAN exposure, systemd unit or scheduled operation is added.
- Fixed literal `GET /api/dns-guard-history?window=1h|6h|24h|7d` only. B3B1's strict Host, optional Origin, Fetch-Site, duplicate and extra-query rejection applies; no request body, arbitrary time, PromQL, IP, port, label, metric selector or redirect. Requests to other routes return 403, other verbs return 405.
- **Only the request handler's manual GET** calls the B3B2A supervised B2 subprocess. A single lock permits **one** history source read at a time; excess in-flight history requests receive 503, not an extra worker. B3B1 also bounds concurrent HTTP workers to eight. No prefetch, page-load calls, background poll, notifications or cached successful results.
- The supervisor independently bounds child lifetime to a **provisional 12 seconds**, stdout to 65,536 bytes *while streaming*, then reaps killed/failed children. The HTTP adapter revalidates the result against exact B1/B2 provenance, fixed requested window and sanitized data, drops arbitrary extra fields, and caps JSON response at 65,536 bytes. On source timeout, error, malformed/oversized response or unexpected exception, it returns neutral `UNKNOWN`; no last successful state survives.
- All success and UNKNOWN responses carry `Cache-Control: no-store, max-age=0`, `Pragma: no-cache`, `nosniff`, CSP `default-src 'none'`, connection-close. The HTTP response body is finalized **before** sending any headers; a failed header write or client disconnect never triggers a second response or retries a source read. A **2-second socket operation timeout** bounds blocking response writes; it is **not** a complete end-to-end deadline. Do not interpret sampled telemetry as DNS uptime, router on/off evidence, or exact switching times.
- Existing V0.5 archive remains **fixed 27 Oct 2026, NOT LIVE**; the V0.4 live tiles and V0.3 opt-in DEMO are unchanged. This PR contains no HCC HTML page, JS import, toolbar, timeline, Caddy proxy, Grafana changes or alerts.

## What is *not* proven

- The 12-second child deadline plus the 2-second socket-write operation timeout are **not** a guaranteed complete HTTP request deadline or server availability SLO. A client disconnect *while the source subprocess is still running* does not proactively cancel that subprocess; the bounded child continues until completion or deadline. Tests cover post-source header/body disconnect safety and lock release, **not** early cancellation of an in-flight B2 reader. A separate cancellation/abort gate remains before any broader exposure or deployment. A single earlier 7d run of 0.138 seconds is not a worst-case bound.
- Binding loopback and inspecting Host/Origin/Fetch-Site is not authentication against hostile local processes. This endpoint is **not approved** for arbitrary shared desktop users, reverse proxies, network exposure or background service.
- No positive real-source output has been exercised by this PR's synthetic tests; real manual API reads require a separate operator acceptance gate after exact-head CI and mock-only results. An opt-in real-source lab read remains a *read* of Fedora VM, not a router query, but must be explicitly authorized separately.
