## Candidate source — independent Blackbox DNS test

The committed monitoring/config/prometheus.yml defines a job named internet_dns with 30-second *source-configured* scrape interval and the Blackbox dns_router_ipv4 module. Monitoring/config/blackbox.yml defines this module as a UDP IPv4 DNS A-record query for example.com and accepts DNS rcode NOERROR.

The exact metric family probe_success{job="internet_dns"} also appears in monitoring/grafana/provisioning/alerting/asus-tuf-alerts.yml and in existing Grafana dashboards. This is a **source-code inventory**, not verification that this precise scrape configuration is currently deployed on Fedora or that fresh samples exist right now.

The DNS job's instance and probe_name labels include target-related details. **Never forward raw labels, raw Prometheus JSON or target addresses to the browser, repository evidence or an LLM.** The later V0.4-C adapter uses fixed, label-free scalar aggregates and rejects non-unique counts to UNKNOWN; it does **not** independently verify all running-job labels or prove an atomic three-query snapshot. Raw private labels must never be returned.

Meaning of a prospective green probe result: one specific configured DNS lookup succeeded at that sample time. It does **not** prove all Pi-hole queries, Unbound/DNSSEC resolution, all clients, continuous DNS service, or the health of the router as a whole.

## Offline V0.4-B model contract

tools/v04_router_dns_model.py is a **pure, network-free function**. It accepts *already independently vetted* evidence with exactly these keys: probe_success (numeric 0/1) and sample_age_seconds (finite seconds, 0..86400), plus an aware observation time. The later V0.4-C adapter adds three fixed aggregate queries, source-cardinality gate and evaluation-time checks, but it does **not** provide a cryptographic source identity proof or an atomic read. **This model does not fetch metrics, read files, open a port or validate source provenance.**

Output states:

- OK / ONE_DNS_PROBE_SUCCEEDED: exactly one fresh success for the particular configured DNS query; nothing broader.
- DEGRADED / ONE_DNS_PROBE_FAILED: exactly one fresh failure. **Not** router DOWN.
- STALE / DNS_PROBE_SAMPLE_TOO_OLD: sample older than proposed 120s; suppress previous success/failure.
- UNKNOWN / EVIDENCE_NOT_VERIFIED: missing/extra fields, invalid flags, malformed or future ages, nonfinite inputs, unavailable or contradictory data.

The proposed 120s TTL is a **lab placeholder**; the declared 30s scrape configuration does not independently prove cadence or collection latency on the running host. The later V0.4-C/D UI integration exists as a manual alternative with a provisional TTL. October 27 operator-reported one-sample source read and a bounded browser/HTTPS acceptance are documented in [the V0.4 preflight](V0.4-LIVE-ROUTER-DNS-PREFLIGHT.md) and the [dated public worklog](../../../../docs/worklog/2026-10-27.md); they are not a long-running host, scrape-config or DNS continuity certification.

## Historical V0.4-C design gate (subsequently implemented in the PR #318 source)

1. Operator accepts the source inventory and explicitly authorizes a narrowly scoped, non-root, read-only probe to 127.0.0.1:8428 (no direct ASUS or Pi-hole access). Inventory whether internet_dns is present and unique in the *running* VictoriaMetrics, not just in Git.
2. Verify three fixed, server-owned PromQL expressions are safe to use: count(probe_success{job="internet_dns"}), sum(probe_success{job="internet_dns"}), and max(time() - timestamp(probe_success{job="internet_dns"})). Require count == 1. **These were proposed at the A/B checkpoint; the later V0.4-C adapter implements them as fixed server-owned local VictoriaMetrics requests.** Validate scalar data, time consistency and query non-atomicity. Do not accept user-supplied job/target/query strings.
3. Return only a sanitized payload with explicit provenance, freshness, failure reason and limitation. Never present stale or absent results as OK.
4. Add mocked HTTP/Origin/Host/CSP and browser tests, then separate operator acceptance through the unchanged loopback Caddy alias. Keep V0.3 unchanged if any gate fails.
