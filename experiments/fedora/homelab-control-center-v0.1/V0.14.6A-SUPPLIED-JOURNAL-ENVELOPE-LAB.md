## Implemented result and trust boundary

The memory-only adapter takes bounded supplied JSONL records, checks declared
origin/address/message fields, classifies three narrow text hints, and maps
them through unchanged [D identity](V0.14.5D-SYNTHETIC-EVENT-IDENTITY-LAB.md)
to one canonical [E snapshot](V0.14.5E-ATOMIC-HANDOFF-LAB.md). It preserves
integer microseconds and distinct cursors at the same time/kind. It does not
drop identity to use A–C's older four-field segment format.

**Supplied JSON can forge every metadata field.** A dedicated test accepts
consistently fabricated fields: this model checks shape/consistency, not
actual journal provenance. Output retains D's `synthetic-unit-envelope`
source and the CLI uses D's public fixture key. There is no trusted reader,
journal descriptor, authenticated export channel or private key lifecycle.

Every row must satisfy the declared origin policy, even an unclassified row
or the final row. Invalid input produces HOLD for the whole batch before a
snapshot is returned. Private message bytes are used for within-call conflict
comparison, never returned or persisted. Additional metadata is ignored after
bounded JSON/field validation and never copied into events.

## Accepted subset and limits

| Field / property | Required contract |
| --- | --- |
| `_SYSTEMD_USER_UNIT` | Exact `dns-guard-monitoring.service`; no fallback to `USER_UNIT`, `SYSLOG_IDENTIFIER` or `_SYSTEMD_UNIT` |
| `_UID`, `_SYSTEMD_OWNER_UID` | Exact decimal strings matching explicit expected UID; policy is an exact integer 1 through 4294967294 |
| `_TRANSPORT` | Exact `stdout` only |
| `_LINE_BREAK` | Must be absent, including empty/null/eof variants |
| `_BOOT_ID`, `__CURSOR` | D's bounded boot/cursor syntax; no claim that an opaque cursor addresses a real entry |
| `__REALTIME_TIMESTAMP` | Exact decimal microseconds, D's 2000–2100 range; all rows nondecreasing |
| `MESSAGE` | Nonempty UTF-8 text, no ASCII control characters; at most 4096 UTF-8 bytes |
| Input | Nonempty exact bytes, at most 1 MiB / 128 nonblank JSONL rows / 16 KiB per row |
| Fields | At most 64 per record, bounded uppercase ASCII names; duplicate JSON keys/nonfinite values rejected |
| Output | Canonical E bytes or `None` when no hints matched; counts only in CLI |

Required scalar fields cannot be arrays, null, numbers or booleans. Extra
metadata may have other JSON values but remains under the input/row/field
budgets. Downstream D's 64 KiB envelope/output limits and E's snapshot limits
also apply. A valid-looking input can exceed a downstream limit and HOLD;
there is no truncation or partial result.

Recognized hints are `SSH_TIMEOUT`, `SSH_AUTH_FAILURE` and
`HTTP_IMPORT_TIMEOUT`, using anchored `ssh:` / `curl:` prefixes and bounded
message text. They describe text patterns, not proven network/DNS root causes.
Manager `COLLECTOR_EXIT_255` attribution is deliberately unsupported. A broad
user-unit query can contain manager/coredump records outside this subset;
this module is not a complete parser for such a query and reads no journal.

The same `(boot, cursor)` with changed time or message is HOLD, including two
unclassified messages or two messages with the same hint. Distinct cursors
remain distinct. A fresh D ledger deduplicates classified repeated records
only inside one call; repeated unknown records count as ignored, not delivered.
No previous snapshot/store is read. Repeating a call repeats its output.

No-match `snapshot=None` is a validated empty selection, not a saved cursor,
delivery ACK or indication that a live journal is complete. No cursor/ACK/
checkpoint changes, replay scheduling, retention or file write exists.

## Standards review and interpretation

Primary documentation reviewed 2026-10-30:

- [systemd journal fields](https://www.freedesktop.org/software/systemd/man/latest/systemd.journal-fields.html): underscore fields acquire trust in the actual journal; stdout credentials may describe its parent connection. Address fields are serialization metadata. This does not authenticate a supplied JSON copy.
- [journalctl JSON and unit filtering](https://www.freedesktop.org/software/systemd/man/latest/journalctl.html): required values may be null/arrays for oversized, repeated or binary data; user-unit queries also include related manager records. This adapter rejects unsupported required representations.
- [Journal JSON format](https://systemd.io/JOURNAL_EXPORT_FORMATS/): serialization differs from a live journal API. Neither parsing bytes nor a message hint establishes provenance.

Rejecting `_LINE_BREAK` and limiting this first model to declared stdout
records are conservative design choices, not claims that other journal
records are invalid. The cursor syntax limit is inherited from D; future
reader/version compatibility and completeness remain unaccepted.
