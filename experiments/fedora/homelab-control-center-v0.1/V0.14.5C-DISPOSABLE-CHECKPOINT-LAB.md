## Implementation contract

1. Use separate, owned `0700` directories for immutable event segments and
   checkpoint state. Recheck owner/mode and use A's nonblocking cooperative
   directory locks. Passing the same directory for both roles fails before
   writing. Final path components are protected by `O_NOFOLLOW`; ancestors
   must already be trusted. Same-UID hostile code and root are outside scope.
2. Verify the whole bounded B snapshot before reading/sending anything to the
   in-process fake receiver. C inherits B's conservative HOLD on ambiguous
   cross-batch rows, interleaved times and snapshot changes. This is a **frozen
   backlog**, not a continuously extensible stream.
3. State contains only `checkpoint.json`: an owned regular `0600`, single-link
   file of at most 256 bytes. Read with `O_NONBLOCK|O_NOFOLLOW`, handle short
   reads, compare metadata before/after, then use B's strict schema/digest/prefix
   validation. FIFO, symlink, unsafe mode, malformed data, unknown names and
   orphan `.checkpoint-<32hex>.tmp` entries cause HOLD. No implicit reset or
   automatic orphan removal.
4. An otherwise empty state directory means a first start. Persist prefix zero
   before the first receive attempt to fix the snapshot. A failed receiver or
   wrong ACK leaves prefix zero. Deleting **all** state is indistinguishable
   from a new session and can cause replay; C does not authenticate state or
   implement a separate durable session ledger.
5. Replace a checkpoint only after comparing its current bytes with the expected
   previous bytes and validating the new checkpoint. First creation must have
   prefix zero; later changes may keep the prefix or advance exactly one.
   This is a cooperative stale-write guard, not proof that an arbitrary caller
   obtained an ACK. The high-level replay function supplies the ACK ordering.
6. Write an exclusive random temp file, enforce `0600` before publication,
   complete the write, `fsync(file)`, `os.replace` within the same state
   directory, then `fsync(directory)`. Ordinary pre-replace errors remove only
   the current operation's temporary name and sync that cleanup. No event
   segment or orphan from another attempt is deleted. Replacing a previously
   verified checkpoint is intentional; only the temporary file is exclusive.
7. Retry the directory sync before another receive and on completion. A failed
   sync returns an error, even if a new checkpoint is already visible. Observed
   file visibility after a failed barrier is **not a durability acknowledgement**.
8. The high-level function sends at most one frozen segment and requires its
   exact filename ACK before storing prefix +1. ACK followed by failure before
   store causes a repeated receive attempt on retry. No exactly-once or real
   Loki delivery claim follows from the checkpoint file.

The only CLI modes are `--self-test` (synthetic memory, no I/O) and `--lab`
(fresh disposable `/tmp` tree, cleanup on exit). Neither accepts an arbitrary
path, journal input or URL. The Python functions are test-library interfaces,
not an independently sandboxed boundary for untrusted callers.

## Failure and restart observations

| Scenario | Observed test expectation |
| --- | --- |
| Close/reopen descriptors | Saved prefix one resumes the second segment |
| Separate Python process | Reads prefix one, receives only segment two and writes prefix two |
| Receiver error / wrong ACK | Prefix does not advance |
| ACK without checkpoint store | Next attempt repeats the same segment |
| Ordinary error after temp-file sync, before replacement | Old checkpoint remains; operation's temp removed |
| Abrupt child exit after temp-file sync | Old checkpoint plus orphan temp; next opener HOLD, no repair |
| Abrupt child exit after replacement, before directory sync | Current filesystem exposes valid acknowledged prefix; next open syncs before progress; power-loss outcome unknown |
| File sync / replace error | No successful return; old checkpoint retained |
| Directory sync error after replacement | No successful return; valid new prefix may be visible |
| Cleanup error | Orphan remains and blocks further replay |
| Changed/corrupt snapshot or checkpoint | No receive attempt and no silent prefix-zero reset |

The child tests use `os._exit` without Python cleanup, with a five-second
subprocess timeout. They test **process termination**, not disk/controller
failure, sudden loss of power, filesystem recovery, a reboot or cross-filesystem
rename. Both directories remain on the test filesystem; no cross-device
checkpoint transaction is implemented.
